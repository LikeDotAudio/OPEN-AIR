# Changelog — 2026-07-06

## EQ cut filters — wink switches, matched selector dials, grey identity

- **SelectorSwitch** (`Knobs/SelectorSwitch/SelectorSwitch.jsx`) gained `hide_title`,
  `hide_value`, and `label_pad` config. The dial radius was being crushed by a fixed
  `-25` label ring + 20+20 title/value reserves (radius went *negative* at 84px).
  Cut-filter selectors now set `hide_title/hide_value` + `label_pad:8`, so the dial
  fills the box and **matches the Freq/Q knob size**; the active choice is still
  shown by the highlighted position label.
- **Shelf & On → wink switches.** The Low/High **SHELF** buttons and the LoCut/HiCut
  **ON** buttons are now `_WinkButton` (latching, publishes 0/1 — same as before).
- **Grey identity.** All LoCut controls (Freq/Q/Slope/Type/Window + the ON wink) are
  **light grey** (`#D5D5D5`); all HiCut controls are **dark grey** (`#555555`),
  replacing the old `#BDBDBD` / `#795548`.

## Phase 4 — Stereo / 5.1 reverb + JFIR bundle format

### JFIR — the OPEN-AIR "JSON FIR" bundle
- New shared builder `libControl/graphing/_dsp/jfir.js` (`window.OaJfir`). A **JFIR** is
  one JSON object holding a preset's **parameters** + the generated **FIR** (one tap
  array per channel, so 5.1 fits in a single file) + the **curve CSV**. Schema v1:
  `{ format:"JFIR", version, kind, label, sampleRate, parameters, fir:{taps,phase,window,
  channels,data}, curve:{columns,csv} }`.
- API: `build()`, `stringify()`, `download()` (→ `.jfir`), `parse()` (validates
  `format==="JFIR"`), `firText()`, and `downloadSeparateFir()` (the "N separate .fir
  files" path). Loaded in `index.html` right after `dsp.js`.

### Reverb — multichannel + JFIR
- `dsp.js`: `synthesizeIR` gained a per-channel `profile` (delay scale / pre-delay
  offset / diffusion + damping boost / gain scale) for decorrelation; new
  `CHANNEL_LAYOUTS` (mono / stereo / 5.1), `channelProfile(ch)`, and
  `synthesizeIRMulti()`. Roles: **C** anchored & drier, **LFE** heavily damped (~10%
  energy), **Ls/Rs** later + more diffuse. Verified: all channels finite, L/R
  decorrelated (sum|L−R| > sum|L|).
- `Reverb.jsx`: reads a **Channels** layout (MQTT `Channels` topic → else
  `config.channels` → else mono), synthesizes one decorrelated IR per channel, and
  plots each as its own colored trace with a legend. Drag handles switched to
  axis-based finders so they're robust to any series count.
- **Export popover** now offers **JFIR** (all channels + params + curve in one bundle),
  **FIR** (primary channel `.fir`), and — in multichannel — **N× separate .fir** files.
  Shows the live layout + channel list.
- `Gui_Frames/5_Samples/7_Reverb/Reverb.json`: added a **Channels** SelectorSwitch
  (Mono / Stereo / 5.1 → `OpenAir/Gui/Rev_Params/Channels`).

### EQ — JFIR export
- `Equalization.jsx`: FIR popover now has **JFIR** and **FIR** buttons. JFIR bundles the
  band parameters, the `generateFIR` taps (single `mono` channel), and the `Freq,Gain`
  curve CSV — same format as the reverb, per the "JFIR always, EQ too" requirement.

### Reverb — IR / EDC visibility toggles
- Added **IR** and **EDC** toggle pills to the toolbar (highlighted when on) so the
  impulse-response trace can be turned off to read the decay envelope alone (and vice
  versa). Toggling re-renders without touching MQTT state.

## Reverb — new IR visualizer + FIR/CSV export

Audit/plan: `Documentation/Changelog/Audit/REVERB PLAN.MD`

### New shared DSP module
- `libControl/graphing/_dsp/dsp.js` (`window.OaDsp`) — extracted the radix-2 FFT,
  Kaiser `I0`, window function, and `_downloadText` from `Equalization.jsx` so every FX
  visualizer shares one copy, and added time-domain primitives: `rt60ToGain`,
  `clampGain`, `combFilter` (one-pole damping in the loop), `allpassFilter`,
  `synthesizeIR` (Schroeder network: 8 parallel feedback combs → 4 series all-passes),
  `energyDecayCurve` (Schroeder backward integral), and peak-preserving `decimate`.
- Loaded in `index.html` **before** the graph components. EQ is unchanged for now
  (keeps its own copy; can be pointed at `OaDsp` later with fallbacks).

### New Reverb component
- `libControl/graphing/Reverb/Reverb.jsx` (`window.Reverb`, JSON type `_Reverb`).
- ECharts plot: **IR** (orange, left axis, auto-scaled to the sub-unity peak) + **EDC**
  (green, right dB axis). Params read from MQTT topics `PreDelay / Decay / Diffusion /
  Size / Damping / Mix` (declarative `topics` map, falls back to
  `OpenAir/Gui/<command>/<Key>`). Uses `useMqttPublish` (not the typo'd `useMqttPublisher`).
- Draggable handles: orange = Pre-Delay, green = Decay/RT60 — 40 ms throttle + a
  `draggingRef` guard against the publish echo (same pattern as EQ).
- **Export toolbar** (mirrors EQ): `CSV` (`TimeMs,Amplitude,DecayDb` per sample) and
  `FIR ▾` popover (Taps / Sample Rate / Phase [default *minimum*, reverb IRs are causal]
  / Window). FIR re-renders the IR at the chosen sample rate — the IR **is** the
  convolution kernel.
- **Stability clamp** on comb feedback gain (`|g| < 0.999`) — verified finite taps even
  at RT60=10 s / size=1 / damping=0.

## Equalization — configurable FIR export

`libControl/graphing/Equalization/Equalization.jsx`

### Export toolbar (dropdowns)
- Replaced the two in-chart echarts buttons ("Export FIR" / "Export CSV") with an
  HTML toolbar above the graph. CSV export is unchanged in output.
- **Export FIR** is now parameterised by four dropdowns, exactly the DSP knobs the
  frequency-sampling method needs:
  - **Taps** — 512 / 1024 / 2048 / 4096 / 8192 / 16384 (filter length).
  - **Sample Rate** — 44.1 / 48 / 88.2 / 96 / 192 kHz (target `fs`; also feeds the
    HP/LP digital biquad so the exported curve matches the destination rate).
  - **Phase** — `Linear` (symmetric taps, N/2 latency) or `Minimum` (real-cepstrum
    reconstruction, no pre-ringing, analog-like).
  - **Window** — Hann / Hamming / Blackman / Kaiser(β=8) / Rectangular.
  - Defaults (1024 / 48 kHz / Linear / Hamming) reproduce the previous hardcoded
    export.

### DSP engine
- Added module-scope helpers shared by the live curve and the export:
  `_fft` (in-place iterative radix-2 FFT/IFFT), `_besselI0`, `_windowVal`, and
  `generateFIR(bands, {taps, sampleRate, phase, window})`.
- `getBiquadGainDB` hoisted to module scope (was defined inline in the MQTT
  effect); gained an `fs` parameter (default 48000) so the export can sample the
  target magnitude at the chosen rate. The live curve calls it unchanged.
- Linear-phase path: target magnitude → IFFT → circular shift to center →
  symmetric window. Minimum-phase path: log-magnitude → cepstrum → causal fold →
  exp → IFFT → tail-only taper. This replaces the old fixed 1024-tap O(N²) DFT,
  so 8k/16k-tap exports are now fast.
- Latest `bands` and `totalData` are stashed in refs each effect run so the HTML
  export buttons never read a stale closure.

### Verification
- Standalone Node checks on the extracted DSP: flat EQ → linear unit impulse at
  center and minimum-phase delta at n=0; a +12 dB / Q2 peak at 1 kHz reconstructs
  to |H(1k)|≈+12 dB, |H(100)|≈0 dB, DC≈unity, with minimum-phase energy centroid
  ~3 vs linear ~1024. Full file transpiles under `@babel/preset-react`.

## Equalization — graph & layout polish

`libControl/graphing/Equalization/Equalization.jsx`

- **Transparent background.** echarts `backgroundColor` and the wrapper div are now
  `transparent` (border softened to `rgba(255,255,255,0.15)`) so the procedural
  panel shows through.
- **Drag no longer fights the MQTT echo.** Dragging a band handle used to publish,
  receive its own echo, re-run the effect, and rebuild/reposition the very circle
  being dragged — causing the bounce/fight. Now a `draggingRef` guard skips the
  handle rebuild while a drag is in flight; `ondragstart/ondragend` manage it, the
  drag stream is throttled to ~40 ms, and the final value is published on
  `ondragend` (guard released one tick later so the trailing echo can't re-fight).

`Gui_Frames/5_Samples/6_EQ/EQ.json`

- **HP/LP moved below the 5 bands.** `Band_Controls` is now a 5-column row
  (Low → High only); LoCut (HP) and HiCut (LP) live in a new 2-column `Cut_Filters`
  row beneath it.
- **HP/LP compacted.** Cut-filter Freq+Q knobs shrunk 120→64 px, laid out Freq|Q
  side-by-side, with a tighter 3-tick scale.
- **Q knobs centered.** LowMid/Mid/HighMid Q knobs are now nested in a 3-column
  `[spacer, Q, spacer]` block (the same trick Low/High use) so they sit centered
  under the LTP instead of left-aligned.
- NOTE: `api/tree.json` embeds each frame's JSON, so `update_tree.py` must be
  re-run after editing any `Gui_Frames/*.json` — otherwise the app renders the
  stale embedded copy (this was why the HP/LP columns "disappeared").

### LTPFader — dual-mode pot (Gain / Q) + data model
`libControl/faders/LTPFader/LTPFader.jsx` — a **new thing**: the travelling pot can
now drive two values from one control.
- **Double-click the cap** toggles Mode 1 (Gain) ↔ Mode 2 (Q). The cap flips colour
  (`cap_color` → `cap_color_2`, default white) and a `MODE 1 · GAIN` / `MODE 2 · Q`
  badge shows which value the rotation drives.
- **Data model** extended to a 4-field compound so nothing is lost on switch:
  `{ value:<linear>, rotValue:<gain>, rotValue2:<Q>, mode:1|2 }`. Legacy
  scalar / `{value,rotValue}` payloads still load.
- Config: `knob_config.rotation2_min/max/default` define the Mode-2 range (Q);
  `cap_color_2` the Mode-2 cap. Drag/wheel sensitivity now scales to the active
  range so Gain and Q feel the same. Middle-click still recenters the active value.
- Enabled only when a second range is configured (`rotation2_*` / `dual_pot`);
  otherwise behaves exactly as before.

### EQ: LTP Mode 2 replaces the separate Q knob
- Each band's LTP now carries Q in Mode 2: `knob_config.rotation2_min/max/default`
  (Q 0.1..24 for mids, 0.1..10 for Low/High) + white `cap_color_2`. The separate
  `Q_Knob` was removed from every band (mids → LTP fills the cell; Low/High →
  `[LTP | Shelf]`).
- Graph `parseBand` reads Q from the LTP's `rotValue2` (falls back to a legacy `/Q`
  topic). `FieldComponent` seeds the LTP compound default with `rotValue2` + `mode`
  so the curve has a sane Q on first paint.

### Live value readout while dragging
- **LTPFader**: the value chip (Freq + active Gain/Q) now shows whenever you're
  dragging, not just when `show_value` is set.
- **Knob** (`Knobs/Knob/Knob.jsx`): a small value chip appears under the dial while
  the knob is being turned.

### LTP middle-button: free-mode drag + double-click normalize
- **Single middle-press = free mode**: fine-adjusts the **potentiometer** (the
  active Gain/Q rotation) by vertical mouse movement (up = increment, down =
  decrement, orientation-independent) from the saved start.
- **Double middle-click = normalize** (recenter the active rotation).
- Parameters on `knob_config`: `middle_fine` (px per unit-norm, default 300),
  `middle_double_ms` (double-click window, default 350), `middle_double_normalize`
  (default true).

### Graph: scroll a dot to adjust Q (now via the LTP compound)
- Scrolling the wheel over any band dot adjusts that band's **Q**. Since Q moved to
  the LTP's `rotValue2`, the graph now republishes the full compound
  `{value, rotValue, rotValue2, mode}` for peaking bands (dragging preserves Q too;
  cut filters still use `/Q`).

### Cut filters: bypass button + uniform, edge-aligned knobs
`Gui_Frames/5_Samples/6_EQ/EQ.json`
- Each cut filter (LoCut/HiCut) gained an **On** toggle → `<topic>/Enable`
  (default 1). Off pulls the filter out of the curve.
- All cut knobs are now the same size (84px); LoCut is **left-aligned** (On at the

`Equalization.jsx` / `FieldComponent.jsx`

### Graph: all minor log lines + translucent backdrop
- The log frequency axis now shows a grid line at **every** sub-decade (2,3,4,…,9),
  not just even — `minorTick.show` enabled; major decade lines brightened (#555)
  so they stand out from minors (#333).
- The graph has a **translucent, configurable backdrop** (default **20% black**,
  currently set to **50%**). `EQ_Graph.cosmetics.bg_color` (`black`/`white`/any css
  colour) + `cosmetics.bg_opacity` (0–100) — e.g. `white`/`10` for a lighter cloud.

### Shelf bands: vertical drag adjusts gain
- In the graph, `lowshelf`/`highshelf` bands were gain-locked (only `peaking`
  allowed vertical gain). Now a `hasGain` check covers peaking **and** shelves, so
  dragging a shelved Low/High dot up/down changes its gain and the handle sits at
  the shelf's gain level (not pinned to 0 dB).

### Cut-filter narrow-window layout
- **Shelf button** relabeled `Shelf Mode` → **`SHELF`** and shrunk (60×40 → 46×32)
  so it stops colliding with the band title in narrow windows.
- **Cut filters stack into two rows** (`layout_columns` 6→3): row 1 `On · Freq · Q`,
  row 2 `Slope · Type · Window` — so the extra knobs fall downward instead of
  squishing across one row. (Left/right edge-alignment dropped in favour of the
  stack; note that true width-based hide/show would need a JS width measurement,
  not the CSS grid.)
