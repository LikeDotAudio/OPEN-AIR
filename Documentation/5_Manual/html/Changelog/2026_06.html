Changelog — 2026-06-24

MQTT GUI topic tree: flat → folder-hierarchy

The web GUI published widget state under a flat, underscore-joined leaf name (OpenAir/Gui/Spectrum_YAK_N9340B_Frequency/...). It now mirrors the Gui_Frames/ folder hierarchy, one folder per topic level:

/Window_1/left_50/top_100/0_Spectrum/10_YAK/1_N9340B/0_Frequency/yak_frequency.json
  ->  OpenAir/Gui/Spectrum/YAK/N9340B/Frequency
  • Added FrontEnd/comMQTT/topicMaker.jsx — window.OaTopicMaker.buildGuiPrefix(filePath). Strips numeric ordering prefixes (0_, 10_), drops window/geometry container folders (Window_n, left/right/top/bottom/display), preserves meaningful trailing device numbers (Channel_1).
  • Changed FrontEnd/frameLayout/LoaderOrchestrator.jsx — derives the topic prefix from the frame's folder path and passes nodeName='' for the root so the flat JSON key isn't re-appended. Falls back to the bare OpenAir/Gui base when there's no filePath (WYSIWYG preview, grab-bag tiles).
  • Changed FrontEnd/Core/Launch/index.html — loads topicMaker.jsx; bumped LoaderOrchestrator.jsx?v=10 for cache-busting.

Notes:

  • The web frontend is the sole publisher of OpenAir/Gui/<widget> topics — no Python/Rust backend change was needed (the backend WidgetRegistry only stores a handed-in topic and has no callers).
  • Old retained flat topics linger on the broker (mosquitto, TCP 1883 / WS 9001) until cleared; refresh the browser to publish the new tree.

Build fixes (blocking openair.py)

  • Restored the seven ST2138 .proto files into BackEnd/ComProtocols/openair-smpte2138/proto/ (were missing; build.rs compiles them under the python feature). Sourced from the upstream st2138-a-main/interface/proto/ set. ⚠️ Currently untracked in git — should be committed so the build is reproducible on a fresh clone.
  • Fixed BackEnd/Core/src/oa_pattern_engine_rs/mod.rs:22 — struct PatternEngine { had its fields and closing brace deleted, leaving an unclosed delimiter that broke the whole oaRustCore lib. Closed as a unit struct (struct PatternEngine;), matching new()'s bare PatternEngine return.

cargo build -p oaRustCore and -p open-air-orchestrator both build clean again.

Launch / runtime

  • Verified the full launcher comes up: oaRustCore loads, open-air-orchestrator runs (core API on 8001), OSC/MIDI/AES70 agents start. (AES70 logs ConnectionRefused to 127.0.0.1:50014 — expected when no AES70 device is up.)
  • Resolved a recurring port-8000 conflict. Only the stale previous openair.py held TCP 8000; the orchestrator's OSC agent uses UDP 8000, a different socket, so they coexist (as the prior run proved). Fix is just to kill the leftover instance — no --port change needed. Note: don't use --port 8001 (that's the orchestrator core port OPENAIR_CORE_PORT); use e.g. --port 8080 if a different web port is ever required. Quick unstick: kill $(ss -ltnp | grep ':8000' | grep -oP 'pid=\K[0-9]+').

Changelog — 2026-06-25

Quiet launcher build output

  • Changed openair.py build_rust() to capture cargo's output and print it only when a build fails. The ~19 k characters of benign warnings (unused imports, dead code, and non_snake_case on the pyo3 module exports — whose names must match the Python import, so they can't be renamed) no longer flood the console on every launch. Build errors still surface in full. Set OPENAIR_VERBOSE_BUILD=1 to stream the full output (warnings included).
