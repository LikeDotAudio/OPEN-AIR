Changelog

A daily log of what's going on in OPEN-AIR — one file per day.

Convention

  • One Markdown file per calendar day, named YYYY-MM-DD.md (e.g. 2026-06-24.md).
  • Top-level heading: # Changelog — YYYY-MM-DD.
  • Group related work under ## sections (a feature, a fix, an investigation).
  • Within a section, lead bullets with a verb: Added, Changed, Fixed, Removed, Investigated. Reference exact files/paths (and line numbers for code) so an entry is actionable later.
  • Append throughout the day rather than rewriting; multiple sessions on the same day share one file.
  • Note follow-ups and caveats (e.g. "untracked in git", "retained topics linger") so nothing silently drops.
