Phase 4 — Stereo / 5.1 reverb + JFIR bundle format

JFIR — the OPEN-AIR "JSON FIR" bundle

  • New shared builder libControl/graphing/_dsp/jfir.js (window.OaJfir). A JFIR is one JSON object holding a preset's parameters + the generated FIR (one tap array per channel, so 5.1 fits in a single file) + the curve CSV. Schema v1: { format:"JFIR", version, kind, label, sampleRate, parameters, fir:{taps,phase,window, channels,data}, curve:{columns,csv} }.
  • API: build(), stringify(), download() (→ .jfir), parse() (validates format==="JFIR"), firText(), and downloadSeparateFir() (the "N separate .fir files" path). Loaded in index.html right after dsp.js.

Reverb — multichannel + JFIR

  • dsp.js: synthesizeIR gained a per-channel profile (delay scale / pre-delay offset / diffusion + damping boost / gain scale) for decorrelation; new CHANNEL_LAYOUTS (mono / stereo / 5.1), channelProfile(ch), and synthesizeIRMulti(). Roles: C anchored & drier, LFE heavily damped (~10% energy), Ls/Rs later + more diffuse. Verified: all channels finite, L/R decorrelated (sum|L−R| > sum|L|).
  • Reverb.jsx: reads a Channels layout (MQTT Channels topic → else config.channels → else mono), synthesizes one decorrelated IR per channel, and plots each as its own colored trace with a legend. Drag handles switched to axis-based finders so they're robust to any series count.
  • Export popover now offers JFIR (all channels + params + curve in one bundle), FIR (primary channel .fir), and — in multichannel — N× separate .fir files. Shows the live layout + channel list.
  • Gui_Frames/5_Samples/7_Reverb/Reverb.json: added a Channels SelectorSwitch (Mono / Stereo / 5.1 → OpenAir/Gui/Rev_Params/Channels).

EQ — JFIR export

Equalization — configurable FIR export

libControl/graphing/Equalization/Equalization.jsx

Export toolbar (dropdowns)

  • Replaced the two in-chart echarts buttons ("Export FIR" / "Export CSV") with an HTML toolbar above the graph. CSV export is unchanged in output.
  • Export FIR is now parameterised by four dropdowns, exactly the DSP knobs the frequency-sampling method needs:
    • Taps — 512 / 1024 / 2048 / 4096 / 8192 / 16384 (filter length).
    • Sample Rate — 44.1 / 48 / 88.2 / 96 / 192 kHz (target fs; also feeds the HP/LP digital biquad so the exported curve matches the destination rate).
    • Phase — Linear (symmetric taps, N/2 latency) or Minimum (real-cepstrum reconstruction, no pre-ringing, analog-like).
    • Window — Hann / Hamming / Blackman / Kaiser(β=8) / Rectangular.
    • Defaults (1024 / 48 kHz / Linear / Hamming) reproduce the previous hardcoded export.

DSP engine

  • Added module-scope helpers shared by the live curve and the export: _fft (in-place iterative radix-2 FFT/IFFT), _besselI0, _windowVal, and generateFIR(bands, {taps, sampleRate, phase, window}).
  • getBiquadGainDB hoisted to module scope (was defined inline in the MQTT effect); gained an fs parameter (default 48000) so the export can sample the target magnitude at the chosen rate. The live curve calls it unchanged.
  • Linear-phase path: target magnitude → IFFT → circular shift to center → symmetric window. Minimum-phase path: log-magnitude → cepstrum → causal fold → exp → IFFT → tail-only taper. This replaces the old fixed 1024-tap O(N²) DFT, so 8k/16k-tap exports are now fast.
  • Latest bands and totalData are stashed in refs each effect run so the HTML export buttons never read a stale closure.

Verification

  • Standalone Node checks on the extracted DSP: flat EQ → linear unit impulse at center and minimum-phase delta at n=0; a +12 dB / Q2 peak at 1 kHz reconstructs to |H(1k)|≈+12 dB, |H(100)|≈0 dB, DC≈unity, with minimum-phase energy centroid ~3 vs linear ~1024. Full file transpiles under @babel/preset-react.

Equalization — graph & layout polish

libControl/graphing/Equalization/Equalization.jsx

  • Transparent background. echarts backgroundColor and the wrapper div are now transparent (border softened to rgba(255,255,255,0.15)) so the procedural panel shows through.
  • Drag no longer fights the MQTT echo. Dragging a band handle used to publish, receive its own echo, re-run the effect, and rebuild/reposition the very circle being dragged — causing the bounce/fight. Now a draggingRef guard skips the handle rebuild while a drag is in flight; ondragstart/ondragend manage it, the drag stream is throttled to ~40 ms, and the final value is published on ondragend (guard released one tick later so the trailing echo can't re-fight).

LTPFader — dual-mode pot (Gain / Q) + data model

libControl/faders/LTPFader/LTPFader.jsx — a new thing: the travelling pot can now drive two values from one control.

  • Double-click the cap toggles Mode 1 (Gain) ↔ Mode 2 (Q). The cap flips colour (cap_color → cap_color_2, default white) and a MODE 1 · GAIN / MODE 2 · Q badge shows which value the rotation drives.
  • Data model extended to a 4-field compound so nothing is lost on switch: { value:<linear>, rotValue:<gain>, rotValue2:<Q>, mode:1|2 }. Legacy scalar / {value,rotValue} payloads still load.
  • Config: knob_config.rotation2_min/max/default define the Mode-2 range (Q); cap_color_2 the Mode-2 cap. Drag/wheel sensitivity now scales to the active range so Gain and Q feel the same. Middle-click still recenters the active value.
  • Enabled only when a second range is configured (rotation2_* / dual_pot); otherwise behaves exactly as before.

EQ: LTP Mode 2 replaces the separate Q knob

  • Each band's LTP now carries Q in Mode 2: knob_config.rotation2_min/max/default (Q 0.1..24 for mids, 0.1..10 for Low/High) + white cap_color_2. The separate Q_Knob was removed from every band (mids → LTP fills the cell; Low/High → [LTP | Shelf]).
  • Graph parseBand reads Q from the LTP's rotValue2 (falls back to a legacy /Q topic). FieldComponent seeds the LTP compound default with rotValue2 + mode so the curve has a sane Q on first paint.

Live value readout while dragging

  • LTPFader: the value chip (Freq + active Gain/Q) now shows whenever you're dragging, not just when show_value is set.

LTP middle-button: free-mode drag + double-click normalize

  • Single middle-press = free mode: fine-adjusts the potentiometer (the active Gain/Q rotation) by vertical mouse movement (up = increment, down = decrement, orientation-independent) from the saved start.
  • Double middle-click = normalize (recenter the active rotation).
  • Parameters on knob_config: middle_fine (px per unit-norm, default 300), middle_double_ms (double-click window, default 350), middle_double_normalize (default true).

Graph: scroll a dot to adjust Q (now via the LTP compound)

  • Scrolling the wheel over any band dot adjusts that band's Q. Since Q moved to the LTP's rotValue2, the graph now republishes the full compound {value, rotValue, rotValue2, mode} for peaking bands (dragging preserves Q too; cut filters still use /Q).
