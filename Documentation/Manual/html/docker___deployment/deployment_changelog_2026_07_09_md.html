CI/CD — push-to-deploy pipeline (replaces manual deploy + local secrets)

Added GitHub Actions push-to-deploy to replace running deploy_FTP_to_like_dot_audio.py by hand with a local .env.

  • New workflows (branch = environment):
    • .github/workflows/deploy-sandbox.yml — push/PR on sandbox,develop → sandbox env
    • .github/workflows/deploy-production.yml — push/PR on main → production env
    • Push deploys; PR only validates (compiles the script), never uploads.
  • FrontEnd/deploy_FTP_to_like_dot_audio.py made CI-capable, backward compatible for local runs:
    • Credentials from OS env first (GitHub Environment secrets), .env fallback.
    • Commit-range incremental mode via DEPLOY_DIFF_BASE/DEPLOY_DIFF_HEAD (git diff --name-only base..head), needs fetch-depth: 0. Null/first-push ref or DEPLOY_FULL_SYNC=1 → full mtime/size sync.
    • Explicit FTPS (FTP_TLS + prot_p()) with plain-FTP fallback (DEPLOY_FTP_PLAIN=1 / DEPLOY_FTP_REQUIRE_TLS=1).
    • Always re-uploads api/tree.json, api/grabbag, index.html; uploads index.html last for near-atomic cutover.
    • Best-effort MQTT build stamp (commit + timestamp + env) after upload.
  • No Node/npm in CI — the site is CDN React/Babel, no bundler.
  • FrontEnd/requirements-deploy.txt (paho-mqtt) and FrontEnd/Documentation/Deploy/CICD.md (secrets + promotion flow) added.

Manual steps remaining (owner): create sandbox/production GitHub Environments with FTP/MQTT secrets; create the sandbox branch; confirm the host accepts explicit FTPS.
