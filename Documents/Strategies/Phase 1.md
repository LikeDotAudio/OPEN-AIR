# Phase 1 Deep Dive — Deploying the `contracts/` Package

*2026-07-17 · Companion to [3_TypeScript_Migration_Plan.md](3_TypeScript_Migration_Plan.md)
Phase 1. This is the deployment strategy: scaffolding, toolchain, codegen
pipeline, CI, and the week-by-week rollout. The prime directive: **a contract
nobody consumes is documentation that lies** — every schema lands with a first
consumer in the same step.*

*Reconciled 2026-07-17 with
[4_Contracts_Structural_Guidelines.md](4_Contracts_Structural_Guidelines.md):
where the two disagreed, the guidelines (inventory-backed) win on schema

## 0. Ground truth this plan is built on

Facts from the repo as of today, because the strategy has to deploy into
*this* codebase, not an idealized one:

- **No Node toolchain exists anywhere.** The only `package.json` in the repo
  is wasm-pack output (`FrontEnd/libControl/Panels/wasm/pkg/`). `contracts/`
  is therefore the package that *introduces* Node/TypeScript to the repo — its
  scaffolding decisions become the house rules for Phase 2's `ui/`.
- **Two disjoint Cargo workspaces**, no root workspace:
  `BackEnd/Core/Cargo.toml` (members: `orchestrator`; root crate `oaRustCore`)
  and `BackEnd/ComProtocols/Cargo.toml` (16 protocol crates). Dependency skew
  is already real: rumqttc **0.24** (orchestrator, yak) vs **0.25.1** (visa,
  midi); editions mixed **2021/2024**; **no `rust-toolchain.toml`**.
- **CI today is deploy-only**: `.github/workflows/deploy-{sandbox,production}.yml`
  are Python FTPS uploads. No Rust build, no tests, nothing that could catch a
  contract violation. Phase 1 adds the repo's first real CI.
- **Two frontend topic utilities that disagree**: `comMQTT/topicMaker.jsx`
  (`window.OaTopicMaker`, builds `OpenAir/Gui/...` prefixes, strips `N_`
  ordering and window/geometry folders) and the older `comMQTT/topicUtils.js`
  (similar normalization, different rules, no `OpenAir/Gui` root). Exactly the
  disease the topic grammar cures — one of these semantics gets canonized, the
  other deleted.
- **The YAK "tree" is not a separate tree.** The YAK repository is scraped out
  of the panel JSON itself: `openair-yak/src/repository.rs` walks
  `Gui_Frames/5_Protocols/10_Yak`, treats folder names as model identity, and
  harvests any `"Execute Command"` node's `"message"` string. So Phase 1's
  layout schema and YAK schema validate the **same files** — one walker, two
  rule sets.
- **Discovery payloads are exploded, not documents**: the VISA agent publishes
  each field as its own retained topic
  (`OpenAir/System/Protocols/visa/Device/{type}/{model}/Dev{n}/{key}`,
  `orchestrator/src/main.rs:284`) with ad-hoc fields (`resource`, `status`,
  `device_type`, `notes`, `last_online` unix-seconds, `connected` 0/1).
  DeviceRecord replaces field-per-topic with one JSON document per device.
- **The only heartbeat in the system is the browser's**
  (`MqttProvider.jsx:77-124`, retained 1 Hz on
  `OpenAir/System/Failover/WEB/Heartbeat/{guid}`). Its payload
  (`guid`, `partition`, `active`, `start_ts`, `timestamp`) is the seed of the
  agent-heartbeat schema — don't invent a new shape, schema the one that works
  and extend it.

### 1.1 Repo placement

```
OPEN-AIR/
├── pnpm-workspace.yaml          # NEW — workspace root; ui/ joins in Phase 2
├── package.json                 # NEW — private root, scripts only
├── .nvmrc                       # NEW — pin Node 24 LTS (matches dev machine)
├── rust-toolchain.toml          # NEW — pin stable (≥1.85; edition-2024 crates need it)
├── contracts/
│   ├── package.json             # @openair/contracts
│   ├── tsconfig.json
│   ├── src/                     # layout per 4_Contracts_Structural_Guidelines §1
│   │   ├── index.ts             # the only public surface
│   │   ├── topics/              # grammar.ts + tree.ts + builders.ts + legacy map
│   │   ├── device-record.ts     # DeviceRecord + status enum + identity rule
│   │   ├── heartbeat.ts         # AgentHeartbeat + LWT helper
│   │   ├── envelope.ts          # {value, full_id} GUI envelope, versioned
│   │   ├── layout/              # node / widget-types / yak-binding / folder-grammar
│   │   ├── yak/                 # v40-definition + verbs now; class/model in Phase 3
│   │   └── log-event.ts         # LogEvent (Phase 4 pre-work)
│   ├── vectors/                 # language-neutral golden test vectors (JSON)
│   │   ├── topics.json
│   │   └── payloads/            # one sample doc per schema, valid + invalid
│   ├── schemas/                 # GENERATED JSON Schema 2020-12 — committed
│   ├── rust/                    # openair-contracts crate
│   │   ├── Cargo.toml
│   │   └── src/
│   │       ├── lib.rs
│   │       ├── gen/             # GENERATED by cargo-typify — committed
│   │       └── topics.rs        # hand-written mirror of the topic grammar
│   └── cli/                     # `openair-validate`
└── ...
```

Decisions baked into that tree:

- **pnpm workspace at the repo root**, even though Phase 1 has one package.
  Phase 2 adds `ui/`; doing the workspace now means zero re-plumbing later.
  Pin the package manager with `"packageManager": "pnpm@<exact>"` (corepack)
  so CI and laptops agree.
- **The Rust crate lives inside `contracts/`, in neither existing workspace.**
  Both workspaces reference it by path (`openair-contracts = { path =
  "../../contracts/rust" }` — adjust per workspace). Rationale: the two
  workspaces already disagree on dependency versions; a crate that sat in one
  would drag that workspace's lockfile politics into the other.
- **Hard rule: `openair-contracts` depends on `serde` + `serde_json` and
  nothing else.** No rumqttc (dodges the 0.24/0.25 skew entirely), no tokio.
  Types and topic strings only. The moment someone wants to add a client
  library to it, the answer is no — that belongs in the agent.
- **Generated code is committed**, both `schemas/` and `rust/src/gen/`. A repo
  where `cargo build` works only after running a Node toolchain is a repo
  where the Rust half stops building the day Node breaks. CI enforces
  freshness instead (§5).

### 1.2 TypeScript setup

- `tsconfig.json`: `"strict": true`, `"exactOptionalPropertyTypes": true`,
  `"noUncheckedIndexedAccess": true`, ESM (`"module": "NodeNext"`). This
  package is greenfield — there is no legacy to accommodate, so maximum
  strictness costs nothing now and sets the bar for `ui/`.
- **zod v4** as the schema language — one definition yields the TS type
  (`z.infer`), the runtime validator, and the JSON Schema
  (`z.toJSONSchema()`, native in v4; no `zod-to-json-schema` shim).
- Build with `tsup` (ESM + `.d.ts`), test with `vitest`. No bundler drama —
  this package has zero runtime dependencies besides zod.
- Export discipline: **`src/index.ts` is the only entry point**; everything
  else is package-private. Consumers importing deep paths is how "one shape"
  becomes five shapes again.

### 1.3 Codegen pipeline (TS → JSON Schema → Rust)

```
src/**/*.ts ──(z.toJSONSchema)──► schemas/*.schema.json ──(cargo-typify)──► rust/src/gen/*.rs
     ▲                                    │
     └── z.infer<> types for ui/          └── also consumable by Python (jsonschema pip)
                                              during the transition
```

- `pnpm gen` runs both stages; `pnpm gen --check` regenerates into a temp dir
  and diffs — that's the CI freshness gate.
- **TS-first, not Rust-first (schemars), deliberately.** The browser and the
  WYSIWYG editor need *runtime* validation (the Phase 2 save-gate, the Phase 3
  WASM dry-runs), which zod gives for free; Rust only needs types + serde,
  which typify generates well. Inverting it would mean hand-writing browser
  validators — the expensive direction.
- Typify config: derive `Serialize, Deserialize, Debug, Clone, PartialEq`;
  **do not** enable `deny_unknown_fields`. Tolerant reader is policy (§2.1).
- Known limit, stated up front: zod→JSON-Schema flattens some refinements
  (branded types, cross-field rules). Those rules still run in TS and in the
  validate CLI; the Rust side gets the structural subset. Anything
  *load-bearing* for Rust (e.g. deviceId format) gets a golden-vector test
  (§4) instead of trusting the schema translation.

## 2. Schema design ground rules

These are the best practices that make the package survive contact with a
live broker. They go in `contracts/README.md` and they are review law.

### 2.1 Retained messages are a database you don't get to migrate

The broker holds retained payloads written by every version of the system
that ever ran — including today's pre-contract shapes. Therefore:

1. **Every payload document carries `schemaVersion: 1`** (integer, required —
   rule R4 in the structural guidelines; `"v"` is rejected as a field name).
   Parsers dispatch on it. Version-less input is, by definition, "v0: the wild west" —
   schemas include a `legacy` variant where a real v0 shape exists (e.g. the
   `_GuiValue`/`subscribe` discovered-frame schema) so validators can *name*
   what they found instead of just failing.
2. **Tolerant reader, strict writer.** Readers: unknown fields ignored,
   missing optionals defaulted (`#[serde(default)]`, zod `.default()`/
   `.optional()`). Writers: always emit the full current shape. Never
   round-trip unknown fields back onto the bus.
3. **Within a major version, evolution is additive-optional only.** Renaming
   or retyping a field is a new major version of that document, and it ships
   with a bus-migration step (a one-shot tool that rewrites or clears the
   retained topics — Phase 4 territory, but the rule exists now).

### 2.2 Conventions

- **Timestamps: ISO-8601 UTC strings** (`z.iso.datetime()`), everywhere. The
  bus is debugged with `mosquitto_sub` and human eyes; `1752786000` is
  hostile, `2026-07-17T20:00:00Z` is not. The two existing unix-seconds fields
  (`last_online`, heartbeat `*_ts`) convert at the contract boundary.
- **IDs are branded and formatted**: `DeviceId` = `{protocol}:{stableKey}`
  (serial when the instrument reports one, else a hash of address+model) —
  documented as *the* identity, replacing "folder name is identity."
- **Enums are closed discriminated unions**, not strings: agent status is
  `'starting' | 'online' | 'degraded' | 'stub' | 'stopping' | 'offline'`
  (guidelines H1); device status is `'discovered' | 'identified' |
  'unresponsive' | 'stale' | 'removed'` (guidelines D3) — which is also what
  makes Phase 0 item 4 (stubs must stop claiming `online`) mechanically
  checkable.
- One document type per file; schema name = file name = exported type name.
- `z.any()` / `z.unknown()` require a `// WHY:` comment and show up in review.

### 2.3 The initial schemas, and their sources of truth

| Schema | Seeded from | Deliberate choices |
|---|---|---|
| `DeviceRecord` | VISA merge object (`main.rs:270-322`) | One JSON doc per device, retained at `OpenAir/Discovery/{protocol}/{deviceId}` — replaces field-per-topic explosion. Fields per guidelines D1: `schemaVersion, protocol, deviceId, deviceClass, make, model, serial?, firmware?, address, rawIdn?, status, firstSeen, lastSeen, notes?, extra?` (typed per-protocol `extra`) |
| `AgentHeartbeat` | `MqttProvider.jsx:77-124` payload | Per guidelines H1: `schemaVersion, agent, status, version?, startedAt, lastBeat, partition?, host?, pid?` (`partition` carried by web sessions); retained, 1 Hz stays; the `active:false` tombstone is replaced by a registered MQTT LWT `{status:"offline"}` (H2) |
| `Layout` (`OcaBin`/`OcaBlock`/field) | Current `Gui_Frames` shape (root key → `{type:"OcaBin", id, geometry, behavior, blocks}`, nested `OcaBlock.fields`, multilingual labels) | Schema the shape **as it exists**, including `_GuiActuator` and the yak `"message"` binding; mark `_GuiValue`+`subscribe` as `deprecated: true` variants so validate reports them by name |
| `YakBinding` + `YakHandlerMsg` | `"Execute Command"` blocks; `openair-yak/src/models.rs:9` | **Two contracts, not one** (guidelines finding #2 — the verbs arrive over MQTT, not in files): the in-file binding block (`enable, yak_type, sub_path, command, input_name?, converter?, marker_number?, trace_number?, trigger_only?`, guidelines L3) *and* the runtime `yak_handler` message + execute envelope incl. `correlation_id` (Y7). The class/model capability split is Phase 3 and gets its own files under `src/yak/` when it lands |
| `LogEvent` | YAK monitor topics | `schemaVersion, source, level, message, at, data?` — pre-work for Phase 4 item 5 |

Schema-ing the mess honestly (deprecated variants included) is the point: the
validate CLI's day-one failure list is only a usable debt inventory if it says
*"legacy `_GuiValue` schema"* rather than *"invalid."*

## 3. The topic grammar — the one part codegen can't do

A topic builder/parser is *behavior*, not shape. It exists twice by design —
`src/topics/` in TypeScript, `rust/src/topics.rs` in Rust — and the two are
kept honest by a shared vector file, not by trust (§4).

### 3.1 The unified tree, with the migration map

```
OpenAir/
├── Discovery/{protocol}/{deviceId}          retained DeviceRecord      (Phase 4 publisher)
├── Gui/{...panelPath}/{field}               live control values        (exists today)
├── Yak/
│   ├── cmd/{verb}/{class}/{model}           command plane              (Phase 3)
│   ├── state/{class}/{model}/{capability}   parsed replies             (Phase 3)
│   └── monitor/{in|out}                     today's yak monitor, moved
└── System/
    ├── Agents/{agent}                       retained AgentHeartbeat
    ├── Log/{source}/{level}                 LogEvent stream            (Phase 4)
    └── Config/{agent}                       retained config            (exists today)
```

Every *current* namespace gets a row in `src/topics/legacy.ts` — a parser +
mapping table, so bridges and the validate CLI can classify old traffic:

| Today (evidence) | Becomes |
|---|---|
| `OpenAir/System/Protocols/visa/Device/{type}/{model}/Dev{n}/{key}` (`main.rs:284`) | `OpenAir/Discovery/visa/{deviceId}` (one doc) |
| `OpenAir/System/Protocols/{proto}` status (`mqtt.rs:80`) | `OpenAir/System/Agents/{proto}` (heartbeat doc) |
| `OpenAir/Protocol/MidiIn/...`, `OpenAir/Protocol/GuiOsc/...`, `OpenAir/Protocol/AES70/...` (`main.rs:67,161,203`) | `OpenAir/Discovery/{midi\|osc\|aes70}/...` + `OpenAir/Gui/...` per role |
| `OpenAir/System/Protocols/yak/monitor/{in,out}` | `OpenAir/Yak/monitor/{in,out}` |
| `OpenAir/System/Failover/WEB/Heartbeat/{guid}` | `OpenAir/System/Agents/web-{guid}` |
| `OpenAir/Gui/#` | unchanged — already right |

**Deployment rule for the collapse:** Phase 1 *defines and documents*; it does
not chase publishers through the codebase. New/rewritten code writes the new
tree only; existing agents migrate in their own phases (VISA in Phase 4,
YAK in Phase 3) using dual-publish during transition. The grammar ships with
`isLegacy(topic)` so the eventual retire step is a grep, not an archaeology
dig.

### 3.2 API shape

```ts
// build — no exported string concatenation, anywhere
Topics.discovery({ protocol: 'visa', deviceId: 'visa:MY12345678' })
  // → "OpenAir/Discovery/visa/visa:MY12345678"
Topics.agents.wildcard()                       // → "OpenAir/System/Agents/+"

// parse — total function, discriminated union out
const t = Topics.parse(raw)
// t: { kind: 'discovery', protocol, deviceId }
//  | { kind: 'gui', segments }
//  | { kind: 'legacy', family: 'systemProtocolsVisa', ... }
//  | { kind: 'unknown', raw }
```

`topicMaker.jsx`'s path→GUI-prefix semantics (strip `N_` ordering, drop
window/geometry folders, keep trailing device numbers) are canonized as
`Topics.gui.fromPanelPath()` — it's the variant the YAK agent's expectations
match. `topicUtils.js` is declared dead in the same commit that lands this
function; it does not get a compatibility wrapper.

## 4. Cross-language honesty: golden vectors

`contracts/vectors/` is the mechanism that keeps two hand-written grammar
implementations and one codegen pipeline from drifting:

- `vectors/topics.json`: a list of `{ build: {...inputs}, topic: "...",
  parsed: {...} }` cases — including every legacy family, every wildcard
  helper, and pathological inputs (empty segments, `+`/`#` injection in a
  deviceId, unicode in panel paths).
- `vectors/payloads/{Schema}/{valid,invalid}/*.json`: sample documents per
  schema, including real captures off today's broker (a `mosquitto_sub -t
  'OpenAir/#' -v` dump is the cheapest test-data generator in existence).
- **Both test suites consume the same files**: vitest asserts
  build/parse/validate against them; `cargo test` in `contracts/rust` does the
  same via `serde_json`. A vector added on one side fails the other side's CI
  until implemented — that's the feature.

This is also the Phase 3 insurance: when the WASM core arrives, it inherits a
vector suite proving the browser build and the native build agree.

## 5. The validate CLI and the ratchet

`contracts/cli` ships `openair-validate` (runs via `pnpm validate`; also the
CI entry point):

```
openair-validate walk FrontEnd/Gui_Frames        # layout + yak binding rules
openair-validate topics --from broker-dump.txt   # classify a topic capture
openair-validate --report json|pretty|summary
```

- Per-file, per-error output with JSON pointers
  (`5_Protocols/10_Yak/1_N9340B/0_Frequency/yak_frequency.json
  #/OcaBin/blocks/... : legacy _GuiValue field`), machine-readable `--report
  json` for tooling, human `pretty` for the terminal.
- Beyond schema: the walker also enforces the *tree* rules the loader
  actually depends on — duplicate class prefixes (`4_DMM_YAK` vs `4_Load_YAK`),
  duplicate model numbers, `_Legacy_Commands/` and `*.json.old` files that the
  YAK loader currently ingests, colliding command names across models.
- Also lints the static config surface (guidelines §7): every `config.ini`
  `topic*` value must parse against the topic grammar — immediately surfacing
  the three-way YAK listen-topic divergence (hardcoded `OpenAir/Gui/#` vs
  config.ini vs code default).
- **Archive markers ride along** (ruling 2026-07-17): every file the
  migration moves, retires, or deletes gets an append-only line in
  `Documents/Strategies/Migration_Ledger.md` (`date | action | old path |
  new path/— | commit | note`), and each shipped rollout step gets a
  `CHANGELOG.md` entry. CI checks the trail the same way it checks the
  ratchet: removals without a ledger line fail the build.
- **The ratchet is the deployment trick that makes day one survivable.** The
  first run's failures are written to `contracts/validate.baseline.json` and
  committed — that file *is* the technical-debt inventory the plan asked for.
  CI then fails only on failures **not in the baseline**; fixing a file and
  running `--update-baseline` shrinks it. The number only goes down; new debt
  is impossible; nobody has to fix 200 files before CI can turn on. (Also
  export the day-one list to `Validations/contracts-debt-inventory.md` so the
  inventory is readable, not just enforceable.)

## 6. CI

One new workflow, `.github/workflows/contracts-ci.yml`, on every PR + main
(the FTPS deploy workflows are untouched):

```yaml
jobs:
  node:      # pnpm install --frozen-lockfile → typecheck → vitest (incl. vectors)
             # → pnpm gen --check   ← fails if schemas/ or rust/src/gen/ is stale
             # → openair-validate (ratchet mode)
  rust:      # cargo test -p openair-contracts (incl. vectors)
             # → cargo build in BOTH workspaces  ← proves the path-dep wiring
             #   from BackEnd/Core and BackEnd/ComProtocols still compiles
```

Supporting pins, all repo-wide firsts and all owed anyway:
`rust-toolchain.toml` (current stable; edition-2024 crates already require
≥1.85, so this legalizes what's implicitly true), `.nvmrc`, exact
`packageManager`. Cache pnpm store + cargo registry; the whole workflow should
stay under ~5 minutes or it will get ignored.

## 7. Rollout — order of operations

Each step is a PR-sized unit that leaves `main` green and ships a schema
**with its first consumer**. No step rewrites an agent.

| Step | Deliverable | First consumer (same step) |
|---|---|---|
| **1. Scaffold** (1–2 d) | Workspace, empty package, toolchain pins, CI skeleton green | CI itself |
| **2. Topic grammar** (2–3 d) | `Topics` build/parse + legacy map + `vectors/topics.json`, TS + Rust | Vector suites both sides; `topicMaker.jsx` internals delegate to the contracts build (via a tiny IIFE bundle or verbatim port — behavior pinned by vectors either way); `topicUtils.js` deleted |
| **3. Heartbeat + DeviceRecord** (2 d) | `AgentHeartbeat`, `DeviceRecord` schemas + payload vectors — **step-by-step deployment strategy: [Phase 1 Step 3.md](Phase%201%20Step%203.md)** (codegen turn-on, dual-topic heartbeat, LWT, VISA replay proof) | `MqttProvider.jsx` heartbeat emits the schema shape **and registers the `{status:"offline"}` LWT (H2)**; a broker-dump replay test proves today's VISA fields map into `DeviceRecord` losslessly |
| **4. Layout schema** (3–5 d, the long one) | `Layout` incl. deprecated variants + yak binding block + `yak_handler` runtime message schema | `openair-validate walk Gui_Frames` runs (incl. config.ini topic lint) — first honest count of the drift |
| **5. Ratchet on** (1 d) | Committed baseline; CI enforces no-new-debt | CI; `Validations/contracts-debt-inventory.md` published |
| **6. Rust adoption seed** (1–2 d) | `openair-contracts` as path dep in both workspaces | `openair-yak` parses one thing through contract types (e.g. its config/monitor payload) — proves the dependency direction before Phase 3 bets on it |

Definition of done — all true at once:

- [ ] `pnpm gen --check`, vitest, cargo test, and both-workspace builds green in CI
- [ ] Every vector passes in **both** languages
- [ ] `openair-validate` runs in CI with the ratchet armed; baseline committed
- [ ] Debt inventory published and linked from the audit README
- [ ] `topicUtils.js` deleted; `topicMaker.jsx` semantics pinned by vectors
- [ ] Zero runtime deps in `@openair/contracts` beyond zod; zero deps in `openair-contracts` beyond serde

## 8. Risks and their counters

- **Schema freezes the bug.** Writing down today's shapes canonizes mistakes.
  Counter: `deprecated: true` variants + the ratchet — the schema *names* the
  debt, versioning provides the exit, and the baseline can only shrink.
- **Codegen drift** (someone edits `gen/` by hand, or edits TS and forgets to
  regen). Counter: `pnpm gen --check` in CI + a `DO NOT EDIT` header +
  `gen/` in `.eslintignore`/CODEOWNERS if it comes to that.
- **Two grammar implementations diverge.** Counter: the vector suite is the
  contract; a grammar change without a vector change is reviewable at a
  glance (and fails one side's CI).
- **Scope creep into agent rewrites.** The gravitational pull of "while I'm
  here, fix the VISA publisher" is strong. Counter: the rollout table's rule —
  Phase 1 touches agents only enough to *prove consumption* (step 6);
  publishers migrate in their own phases with dual-publish.
- **Retained-message poison**: old payloads outlive every deploy. Counter:
  §2.1 is non-negotiable — versioned docs, tolerant readers, and no reader
  ever assumes the bus contains only current-shape data.
- **zod major-version churn.** Counter: exact-pin zod; the public API of the
  package is types + validators + `Topics`, so a future zod swap is internal.
