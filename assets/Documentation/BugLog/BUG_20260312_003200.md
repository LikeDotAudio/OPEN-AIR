# Bug Log: BUG_20260312_003200

## **Issue**
**User Requirement**: "When you decouple control (the "Splice") from state feedback (the "Link"), motorized faders, endless encoders, and bi-directional GUIs are notorious for causing infinite MIDI/OSC/MQTT echo loops."
**Problem**: The system lacked a formal way to track the original source of an action, causing devices to re-broadcast state updates they themselves initiated.

## **Root Cause**
1.  **Missing Origin Context**: The `ProtocolRouter` and `SplinkerManager` were generating new IDs for brokered messages, losing the link to the original physical or virtual control.
2.  **Lack of Message Intent**: No distinction existed between an "Action" (Splice) and "Feedback" (Link).
3.  **Chatty Updates**: High-frequency fader movements caused hundreds of updates with no "settled" state, making it difficult for motorized hardware to find a final resting position.

## **Investigation**
1.  **Code Review**: Confirmed `ProtocolRouter` was using session-level GUIDs for loop prevention, which is effective for partition-level loops but insufficient for device-level echo suppression.
2.  **Reproduction**: `reproduce_feedback_loop.py` demonstrated that reflecting a message back to its source topic would trigger a new action if the source ID was not preserved.

## **Resolution: Splinker Anti-Feedback Spec**
1.  **Unified Schema**: Added `msg_guid`, `msg_type`, and `origin_source` to the `ProtocolRouter.ingest` pipeline.
2.  **Brokered Identity**: Updated `SplinkerManager` (`_broker_splice` and `_broker_link`) to preserve the `origin_source` and `msg_guid` of the triggering message while setting `msg_type` to `LINK_FEEDBACK`.
3.  **The Golden Rule**: Updated `StateMirrorEngine.sync_incoming_mqtt_to_gui` to perform a "Silent Update" if the `origin_source` matches the widget's ID. This updates the UI visual without re-broadcasting.
4.  **Settling Engine**: Implemented a 50ms debounce timer in `ProtocolRouter` that fires a final `is_settled: True` message after a stream of `SPLICE_ACTION` messages stops.

## **Verification**
1.  **Spec Compliance**: `verify_anti_feedback.py` confirmed that brokered messages correctly carry the `origin_source` of the fader that started the movement.
2.  **Echo Suppression**: Verified that `LINK_FEEDBACK` messages with matching `origin_source` result in silent UI updates.
3.  **Settling Verification**: Confirmed the delivery of a final `is_settled: True` message exactly 50ms after the last action.
