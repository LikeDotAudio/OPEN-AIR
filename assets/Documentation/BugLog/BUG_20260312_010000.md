# Bug Log: BUG_20260312_010000

## **Issue**
**User Analysis**: "The network reflection is incredibly stubborn. The partitions are still eager to echo states back and forth because they don't have a concept of "ownership" over a parameter during an active physical or visual movement."
**Problem**: Persistent infinite loops (ping-pong) between CORE and UI partitions during active user interaction and initial cache restoration.

## **Root Cause**
1.  **Trust-based Suppresion**: The system relied on the network layer to suppress loops, but multiple instances independently responding to the same "external" state change created an echo chamber.
2.  **No Interaction Context**: Widgets had no way to signal they were "busy" or "owning" a value, causing them to fight the network (motor fighting/visual stutter).
3.  **Boot Race**: Initial state restoration flooded the network, causing both partitions to start competing settling timers.

## **Resolution: Interaction Lock Protocol**
1.  **Widget Mutex**: Injected `is_locked` boolean into `Fader`, `Knob`, `Selector`, and `Toggle` widgets.
2.  **The blockade**: Updated `StateMirrorEngine.sync_incoming_mqtt_to_gui` to check `is_locked`. If True, the incoming network message is dropped. The Human is master.
3.  **Hardware Muting**: Updated `MidiManager` to track hardware-level interaction locks. If a human is touching a physical fader, incoming MIDI-TX commands are suppressed to prevent motor fighting.
4.  **Broker Blockade**: Updated `ProtocolRouter` to track locked parameters. If a parameter is currently receiving a flood of `SPLICE_ACTION` (original movements), it rejects all `LINK_FEEDBACK` reflections for that topic until it settles.
5.  **BOOT Tagging**: Labeled initial DISK loads with a `boot: True` tag, allowing silent acceptance by other partitions without starting new settling timers.

## **Verification**
1.  **Interactive Stability**: Verified that moving a GUI fader rapidly no longer causes visual "stutter" from network echo.
2.  **Motor Suppression Simulation**: Confirmed that MIDI Out commands are ignored while a simulated hardware touch is active.
3.  **Cache Restoration**: Confirmed that BOOT messages complete initialization without triggering infinite settling cycles.
