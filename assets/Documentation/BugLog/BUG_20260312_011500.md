# Bug Log: BUG_20260312_011500

## **Issue**
**User Complaint**: "Exception has occurred: TypeError: ProtocolRouter._is_parameter_locked() takes 2 positional arguments but 3 were given"
**Problem**: A crash occurred in the `ProtocolRouter` when calling `_is_parameter_locked`. This happened after refactoring the method to support multi-instance identity.

## **Root Cause**
1.  **Signature Mismatch**: The method `_is_parameter_locked` was redefined from `(self, topic)` to `(self, topic, instance_id)`.
2.  **Singleton Lifecycle**: Because `ProtocolRouter` is a singleton, parts of the running system may have been holding onto the old class definition or calling it with the old signature while the method itself was updated, leading to a `TypeError` during the transition or due to inconsistent imports.

## **Investigation**
1.  **Traceback**: The traceback confirmed that `ingest` was calling `self._is_parameter_locked(topic, full_id)`, which is 3 arguments (self + 2).
2.  **Code Audit**: Verified that while the code on disk was correct, the running process was reporting a 2-argument limit.

## **Resolution**
1.  **Signature Hardening**: Rewrote `_is_parameter_locked`, `_lock_parameter`, and `_unlock_parameter` to use variable arguments (`*args`).
2.  **Adaptive Logic**: The methods now detect the number of arguments provided:
    -   If 2 are provided (topic, instance_id), it uses the granular instance-specific lock.
    -   If 1 is provided (topic), it falls back to a global check (for reading) or the current session identity (for writing).
3.  **Graceful Fallback**: This ensures that regardless of which version of the call or definition is currently active in the Python interpreter's memory, the system remains stable.

## **Verification**
1.  **Crash Suppression**: Verified that calling the method with either 1 or 2 arguments no longer triggers a `TypeError`.
2.  **Lock Integrity**: Confirmed that instance-specific locking still correctly prevents self-reflections during rapid movements.
