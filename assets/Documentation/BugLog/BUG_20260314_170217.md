# BUG: GUI Layout Regression for Directory-Based Notebooks
- **ID**: 20260314_170217
- **STATUS**: RESOLVED
- **SEVERITY**: 2 (High)
- **COMPONENT**: `managers.Display.parser.layout_parser`

## Issue
The GUI was failing to create `ttk.Notebook` widgets based on numbered subdirectory naming conventions (e.g., `0_MQTT`, `1_Setup`). For example, the "Setup" tab, which should contain several sub-tabs, was rendering incorrectly because the layout parser was no longer identifying the structure as a notebook. This was a regression introduced during a recent refactoring.

## Root Cause Analysis
The `_parse_directory_listing` method in `layout_parser.py` is the designated fallback for creating layouts when a `layout.json` file is not present. During a previous refactoring, the logic to detect numbered subdirectories and interpret them as a `notebook` layout was inadvertently removed.

The function would correctly identify `horizontal_split` and `vertical_split` layouts from names like `left_50`, but it would then fall through to a simple directory listing for any other case. It was no longer checking for subdirectories starting with digits (e.g., `0_`, `1_`) which is the convention for defining a notebook layout. Consequently, the parser returned a generic `directory_listing` type, and the `gui_display` builder did not create the expected `ttk.Notebook`.

## Resolution
The notebook-parsing logic was restored to the `_parse_directory_listing` method in `managers/Display/parser/layout_parser.py`.

1.  After checking for split-pane layouts (`left_`, `top_`, etc.), the function now explicitly checks for subdirectories whose names begin with a digit.
2.  If found, it correctly identifies the layout type as `notebook`.
3.  It then iterates through these numbered directories, sorts them, and generates the `tabs` data structure required by the `gui_display` builder. This includes creating a user-friendly `display_name` from the directory name (e.g., `0_Fleet_Manager` becomes "Fleet Manager").
4.  The logic to filter out empty directories using `_scan_for_gui_files` is also preserved to prevent the creation of empty, non-functional tabs.

This change restores the critical functionality of defining notebook layouts via directory naming conventions, fixing the regression.

## Verification
After the fix, the "Setup" tab and any other sections using numbered subdirectories now correctly render as `ttk.Notebook` widgets with the appropriate sub-tabs. The application UI is fully restored to its intended structure.
