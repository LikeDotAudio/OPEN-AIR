# Bug Log: BUG_20260315_015500
**Date:** Sunday, March 15, 2026  
**Module:** `oaGuiManager.factory`, `oaGuiBuilder`  
**Severity:** Priority 1 (Critical Crash)

## Issue
The application crashed immediately during the UI build process with:
`AttributeError: type object 'WidgetRegistry' has no attribute 'get_registry'`.
After fixing that, the system would fail with `AttributeError: 'DynamicGuiBuilder' object has no attribute 'make_slider_value'` (and others).

## Root Cause
A major refactor of the `DynamicGuiBuilder` and `GuiWidgetFactoryMixin` was left in an inconsistent state:
1.  `WidgetRegistry` was introduced to replace the legacy factory, but its API was not fully implemented (`get_registry` was missing).
2.  `GuiWidgetFactoryMixin` was emptied out to eliminate hardcoded imports, but `factory_mapping.py` still referred to the old `self.make_...` instance methods which no longer existed on the builder.

## Resolution
1.  **Registry Completion**: Implemented `get_registry()` class method in `WidgetRegistry` to return a copy of the internal registry.
2.  **Modular Factory Mapping**: Refactored `managers/Display/factory/core/factory_mapping.py` to use `self._lazy_wrap` for ALL core/legacy widgets. This allows the builder to dynamically import and call widget creators on-demand without needing them as mixins.

## Verification
- Created `reproduce_bug.py` which confirmed the `AttributeError`.
- Created `test_factory.py` which verified that the new lazy-loaded mappings resolve correctly to their creator methods.
- Both tests pass with the final implementation.

## Forensic Evidence
Log trace showed failure in `_construct_dynamic_gui` (UniversalGuiLoader) -> `__init__` (DynamicGuiBuilder) -> `_initialize_widget_factory` (GuiWidgetFactoryMixin). This confirmed the failure was at the very start of the widget factory initialization.
