# Bug Report: Log Filter Engine Initialization Failure

## [2026-03-15 22:45:00]
**Status**: RESOLVED
**Priority**: 1 (Critical/Crash)

### Issue
The system failed to launch the Core partition due to an `ImportError` in `managers/manager_launcher.py`. The error originated from an attempt to import `initialize_filter_engine` from the `workers.logger.logger` module, where it was not defined. Furthermore, the `workers.logger.log_filter_engine` module contained multiple case-sensitivity errors and incorrect API calls for the MQTT subscriber router.

### Root Cause
1.  **Incorrect Import Path**: `manager_launcher.py` had an outdated or speculative import path for `initialize_filter_engine`, likely assuming it was part of the primary `logger.py` module.
2.  **Class Name Case-Sensitivity**: `log_filter_engine.py` was trying to import `MQTTSubscriberRouter` but the actual class name in `mqtt_subscriber_router.py` is `MqttSubscriberRouter`.
3.  **API Mismatch**: `LogFilterEngine` was calling `self.mqtt_router.subscribe()` which does not exist on `MqttSubscriberRouter` (correct method is `subscribe_to_topic()`).
4.  **Payload Handling Error**: `LogFilterEngine.handle_filter_update` was expecting a string payload but `MqttSubscriberRouter` callbacks receive a `MqttMessage` object.

### Resolution
1.  **Update Imports**: Corrected `managers/manager_launcher.py` to import `initialize_filter_engine` from `workers.logger.log_filter_engine`.
2.  **Standardize Class Names**: Updated `workers/logger/log_filter_engine.py` to use `MqttSubscriberRouter` throughout, including imports, comments, and the mock class.
3.  **Align with MQTT API**: Updated the subscription call to `subscribe_to_topic()`.
4.  **Enforce Payload Decoding**: Modified `handle_filter_update` to correctly handle `MqttMessage` by using its `get_json_payload()` method.

### Verification
-   Verified successful imports of both `managers.manager_launcher` and `workers.logger.log_filter_engine` via CLI check.
-   Code review of `MqttSubscriberRouter` confirmed `subscribe_to_topic` is the correct method name.
-   Code review of `MqttMessage` confirmed `get_json_payload()` is the correct way to parse incoming JSON rules.
