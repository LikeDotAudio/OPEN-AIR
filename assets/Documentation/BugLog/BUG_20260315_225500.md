# Bug Report: UI Rendering Failure (Empty Screen) due to Cache Corruption

## [2026-03-15 22:55:00]
**Status**: RESOLVED
**Priority**: 1 (Critical/Crash - Functional Block)

### Issue
After an initial successful build, subsequent application restarts resulted in an empty GUI with no panels or widgets being drawn. The logs showed the build finishing successfully, but with empty layout data for the root `display` directory.

### Root Cause
A logic error in `DirectoryBuilderMixin._get_layout_info` caused the layout cache to become corrupted. 

1.  On a cache hit where the directory `mtime` matched, the code was retrieving the **already-normalized** layout data from the cache.
2.  It then incorrectly passed this normalized data back into `LayoutParser.parse_layout_data`.
3.  `parse_layout_data` expects **raw** layout dictionary input (where keys like `panels` or `tabs` are at the top level). 
4.  Since the input was already normalized (keys were inside a nested `data` dictionary), the parser failed to find the required fields and returned empty lists.
5.  This empty result was then returned to the builder (causing the empty UI) and subsequently **saved back to disk**, permanently corrupting the cache for that path.

### Resolution
1.  **Code Fix**: Modified `DirectoryBuilderMixin._get_layout_info` to return the `cached_entry` directly upon a cache hit with a matching `mtime`. This bypasses the redundant and incorrect re-normalization pass.
2.  **System Cleanup**: Deleted the corrupted `DATA/cache/layout_cache.json` file to force the application to perform a clean directory scan and rebuild a healthy cache.

### Verification
-   Verified the corruption mechanism by tracing `LayoutParser.parse_layout_data` behavior with already-normalized input.
-   Confirmed that `LayoutCacheManager` correctly restores `pathlib.Path` objects upon loading, making the direct return of cached data safe.
-   Visual confirmation (simulated) that the root build pass now receives the correct panel list.
