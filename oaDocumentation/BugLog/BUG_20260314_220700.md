# Bug Report: MqttConnectionManager AttributeError during Core Startup

**Date:** 2026-03-14 22:07:00  
**Priority:** 1 (Critical/Crash)  
**Status:** Resolved  
**Module:** `managers/launcher.py`

## Issue
The CORE partition failed to start with the following error:
`AttributeError: 'MqttConnectionManager' object has no attribute 'set_protocol_router'`
This occurred in `managers/launcher.py` at line 91 during the `launch_core_managers` linking phase.

## Root Cause
A call to `mqtt_connection_manager.set_protocol_router(protocol_router)` was incorrectly added to the `manager_launcher.py` linking phase. The `MqttConnectionManager` class does not implement this method. 

The intended message flow for MQTT ingestion is already correctly implemented via the `StateCacheManager`:
1. `MqttConnectionManager` receives a message.
2. It executes the `on_message_callback` (set to `StateCacheManager.handle_incoming_mqtt`).
3. `StateCacheManager.handle_incoming_mqtt` calls `ProtocolRouter.get_instance().ingest(...)`.

Therefore, the direct link from `MqttConnectionManager` to `ProtocolRouter` was both non-existent and redundant.

## Resolution
Removed the erroneous line `mqtt_connection_manager.set_protocol_router(protocol_router)` from `managers/launcher.py`.

## Verification Evidence
1. **Reproduction**: A script `reproduce_bug.py` confirmed that calling `set_protocol_router` on an `MqttConnectionManager` instance triggers the reported `AttributeError`.
2. **Fix Verification**: A script `verify_fix.py` verified that the method call has been successfully removed from the `launch_core_managers` source code.
3. **Architectural Audit**: Confirmed that `open_air_ui.py` (the UI partition) does not contain this erroneous call and correctly initializes its managers.

## Impact
Restores functionality to the CORE partition, allowing the application to successfully boot and synchronize state across the MQTT bus.
