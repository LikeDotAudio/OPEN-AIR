# Bug Report: BUG_20260329_214500

## Issue
SNMP state file was not being updated with current values from the MQTT state cache. While the bridge was "running", it only reflected the initial OID map but never synced actual data changes.

## Root Cause
The `SnmpStatePersister` background thread was iterating over the `OidMapConverter.oid_map` but never calling `build_oid_map()` to refresh it. Furthermore, `build_oid_map()` contained a redundant internal lock that could have caused performance bottlenecks or deadlocks when called from an already-locked context.

## Resolution
1.  **Sync Trigger**: Modified `SnmpStatePersister._persistence_loop` to explicitly call `oid_map_converter.build_oid_map()` inside its state lock.
2.  **Snapshot Consistency**: Updated the loop to take a single `cache_snapshot` and pass it to the converter, ensuring that the OID mapping and value extraction are performed against the same point-in-time data.
3.  **Lock Optimization**: Refactored `OidMapConverter.build_oid_map()` to remove redundant internal lock acquisition, delegating thread safety to the orchestrator.

## Verification
1.  Verified that the `_persistence_loop` now correctly refreshes the OID map.
2.  Manual code audit confirms that data from the state cache now flows into the OID map items used for file generation.
