# Bug Report: BUG_20260329_231000

## Issue
The main application GUI appeared empty for several modules (Console, Scan, etc.), showing only the background despite logs indicating that widgets were being created.

## Root Cause
1.  **Missing Grid Calls**: The `AsyncGridRenderer` was failing to call `.grid()` on several structural widget types, specifically `OcaArray` and custom structural adapters. These widgets were created but remained invisible because they were not attached to the parent's geometry manager.
2.  **Inconsistent Grid Logic**: Functional widgets (deferred for batch processing) were using incorrect row/column coordinates because the renderer was not respecting explicit `layout` overrides for deferred items.

## Resolution
1.  **Structural Grid Enforcement**: Updated `oaGuiBuildShell/Workers/async_grid_renderer.py` to explicitly call `.grid()` on all structural widgets created during the synchronous pass.
2.  **Explicit Layout Resolution**: Fixed the deferred widget logic to correctly prioritize `cr` (calculated row) and `cc` (calculated column) based on both JSON layout metadata and auto-incrementing grid flow.
3.  **Clean Separation**: Centralized all grid placement within the renderer, removing experimental or redundant grid calls from individual widget creators (like `BuilderArrayCreator`).

## Verification
1.  Manual code audit confirms that every code path in `_process_fields` that instantiates a widget now ends with a `.grid()` call.
2.  Verified that `OcaArray` and `plot_widget` (Scan tab) are now correctly included in the grid orchestration.
