# Bug Report - 2026-04-02 02:00:00

## Issues

This report details a batch of bugs fixed on 2026-04-02. The issues involved a `TypeError` when persisting the state cache using the Rust engine, and a persistent `ImportError` preventing the `BlueprintParser` from being loaded from its compiled Rust extension.

## Root Causes & Resolutions

### 1. TypeError in CacheSaveEngine

*   **Issue**: `TypeError: argument 'data': 'StateRegistryCore' object cannot be converted to 'PyDict'` in `oaStateCache/Core/cache_save_engine.py`.
*   **Root Cause**: The `_worker` method in `CacheSaveEngine` attempted to pass the Rust `StateRegistryCore` object (`self.cache`) directly to `flusher_instance.flush_async()`. PyO3 could not automatically coerce this custom Rust object into a Python dictionary (`PyDict`).
*   **Resolution**: Modified the code to check if `self.cache` has a `to_dict` method (which the Rust implementation provides). If so, it calls `self.cache.to_dict()` to generate a standard dictionary before passing it to the flusher. Otherwise, it falls back to `dict(self.cache)`.

### 2. ImportError for BlueprintParser

*   **Issue**: `ImportError: cannot import name 'BlueprintParser' from 'oablueprintparser_rs'` in `oaGui/FileReaders/json_blueprint_reader.py` and `oaGui/FileReaders/oaBlueprintParser_rs/compiler_hook.py`.
*   **Root Cause**: The `maturin` develop command generated an `__init__.py` wrapper for the `oablueprintparser_rs` Python package that failed to correctly expose the `BlueprintParser` class from the underlying compiled `.so` extension (named `oablueprintparser_rs.cpython...so`). The class was successfully compiled but hidden within the `oablueprintparser_rs.oablueprintparser_rs` namespace.
*   **Resolution**: Updated all import statements across `json_blueprint_reader.py` and `compiler_hook.py` to bypass the generated `__init__.py` wrapper and import the class directly from the compiled shared object: `from oablueprintparser_rs.oablueprintparser_rs import BlueprintParser`.

## Verification

The fixes have been applied and the application should now successfully save the state cache to disk and instantiate the `BlueprintParser` during the GUI bootstrap sequence without raising exceptions.
