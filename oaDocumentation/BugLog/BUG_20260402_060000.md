# Bug Report - 2026-04-02 06:00:00

## Issues

This report details the systematic resolution of `ModuleNotFoundError` exceptions related to naming mismatches between Rust crate project names and Python import statements.

## Root Causes & Resolutions

### 1. Project Name Mismatch in pyproject.toml

*   **Issue**: `ModuleNotFoundError: No module named 'oaptpclock_rs'` and similar errors.
*   **Root Cause**: Several Rust extensions had `pyproject.toml` files where the `[project].name` field was either mixed-case or hyphenated (e.g., `oaPTPClock_rs`, `oaptpclock-rs`). This caused `pip` to register the package under a name that didn't strictly match the lowercase underscored name expected by the Python importer and the project's absolute import standard.
*   **Resolution**: Audited every Rust extension in the codebase and updated their `pyproject.toml` files to use a standardized lowercase, underscored project name (e.g., `oaptpclock_rs`).

### 2. Missing pyproject.toml Files

*   **Issue**: Installation failures for certain Rust modules during bootstrap.
*   **Root Cause**: Modules such as `oaDiskFlusher_rs`, `oaNeedleGeometry_rs`, `oaOSCCore_rs`, and `oaVisaScanner_rs` were missing `pyproject.toml` files entirely, preventing `maturin develop` from correctly registering them as Python packages in the virtual environment.
*   **Resolution**: Created standardized `pyproject.toml` files for all identified missing modules.
