# Bug Report - 2026-04-02 07:00:00

## Issues

This report details the implementation of a system-wide "Graceful Rust Failure" pattern to prevent `ModuleNotFoundError` and other initialization exceptions from causing total application crashes.

## Root Causes & Resolutions

### 1. Brittle Rust Imports

*   **Issue**: The application would fail to boot if a single Rust extension was missing or failed to compile, primarily due to direct, unprotected imports at the module level.
*   **Root Cause**: Lack of `try-except` wrappers around `ensure_compiled()` calls and Rust module imports.
*   **Resolution**: Implemented a robust import pattern across all high-impact modules:
    *   Wrapped `ensure_compiled()` and `import` statements in `try...except (ImportError, Exception)` blocks.
    *   Introduced a `HAS_RUST` boolean flag to track extension availability.
    *   Updated classes (e.g., `PtpClock`, `SnmpAgent`, `StateManager`) to check `HAS_RUST` during `__init__`.
    *   Provided safe Python fallbacks (like `PythonStateRegistry`) or graceful method-level skips (returning empty dicts/lists) when Rust is unavailable.

## Affected Modules (Hardened)

The following core modules were updated with graceful failure logic:
- `oaPTP` (Clock and Packet Parser)
- `oaComProtocols.oaComMQTT` (MqttRouter)
- `oaComProtocols.oaComSNMP` (SnmpAgent)
- `oaComProtocols.oaComEmber` (EmberParser)
- `oaGuiEditorWYSIWYG` (StateManager)
- `oaGuiManager` (BlueprintLoader and FastScanner)
- `oaComProtocols.oaComVisa` (Visa Probing)
- `oaGuiBuilder` (Geometry Math)
- `oaTranslator` (YakTranslator)

## Verification

The system was tested by simulating a missing `oaptpclock_rs` module. The application successfully bypassed the missing dependency, logged a warning, and continued the boot sequence for both the Core and UI partitions, demonstrating significantly improved resilience.
