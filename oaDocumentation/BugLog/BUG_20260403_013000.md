# Bug Log: BUG_20260403_013000

## Issue: Indentation Errors and Repetitive MQTT Processing Failures
The system was reporting multiple `IndentationError`s during module loading for `yak_monitor.py` and `Showtime.py` (via `from_soundbase_pdf_v2.py`). Additionally, `oaStateCache` was reporting repetitive failures when handling MQTT messages for specific topics, and the system was experiencing intermittent `Code -11` (Segment Fault) crashes.

## Root Cause Analysis
1.  **Syntax Errors**: `yak_monitor.py` had an empty `if` block followed by unindented imports. `from_soundbase_pdf_v2.py` had multiple blocks within a loop that were over-indented, likely due to a copy-paste or refactoring error.
2.  **Generic Error Catching**: `oaStateCache` caught all exceptions during MQTT handling but only logged a generic message without a traceback, masking the actual failure (likely related to payload format or Rust extension interaction).
3.  **Unprotected Serialization**: `ProtocolRouter`'s MQTT dispatcher was calling `orjson.dumps` without error protection, which can cause segment faults if it encounters recursive objects or hits depth limits in certain environments.

## Resolution
1.  **Fixed Indentation**: Properly structured the `if str(root_path) not in sys.path` block in `yak_monitor.py` and aligned the text processing logic in `from_soundbase_pdf_v2.py`.
2.  **Forensic Enhancement**: Updated `handle_incoming_mqtt` in `oaStateCache` to log full tracebacks using `traceback.format_exc()`.
3.  **Robust Dispatch**: Wrapped MQTT payload serialization in a `try-except` block to prevent crashes from invalid data structures.
4.  **Log Noise Reduction**: Updated `LoaderFacade` to skip GUI class warnings for gatekeeper and test files.

## Verification Evidence
- **Syntax Check**: All fixed files passed `python3 -m py_compile`.
- **Log Integrity**: Verified that `matrix_log` calls remain consistent with the project's [INBOUND]/[OUTBOUND] architecture.
