# Bug Report: GraphPlotter Display Issue
**Date:** 2026-04-03 02:16:30
**Priority:** 1 (Critical/Crash)

## Issue
The `GraphPlotter` (used for `plot_widget`) was failing to render anything inside an `OcaBin` container when the `sticky` property in its layout config was empty (`""`). Because the grid layout manager wasn't stretching the `tk.Frame`, the widget defaulted to a requested size of `0x0`, rendering it invisible.

## Root Cause
In `oaGuiElements/Core/graphing/graphing/dynamic_graph.py`, `GraphPlotter.__init__` was calling `super().__init__(parent, **kwargs)` without injecting explicit `width` and `height` dimensions. It then correctly disabled child propagation (`self.pack_propagate(False)` and `self.grid_propagate(False)`) to prevent vibrating resize loops, which meant the frame relied entirely on external grid weights or initial sizes. Without initial sizes, it remained invisible if `sticky` was disabled.

## Resolution
Modified `dynamic_graph.py` to extract `width` and `height` from the JSON `geometry` and `layout` structures, and explicitly pass them into `kwargs` for `super().__init__`. This ensures the `GraphPlotter` frame starts at the requested size (minimum `100x50`) instead of `0x0`, displaying perfectly regardless of grid stretching logic.

## Verification
- Added `kwargs["width"]` and `kwargs["height"]` directly into the `__init__` logic of `GraphPlotter`.
- Confirmed this initializes the `tk.Frame` with the correct starting dimensions, satisfying `pack_propagate(False)`.
- Issue is fully resolved.
