# BUG LOG: 20260403_004000
# Date: 2026-04-03
# Issue: Core Exited (Code -11) Segmentation Fault and NoneType Errors
# Root Cause: Stack overflow in Rust persistence engine and unhandled None values in SNMP observer.

## Analysis
- **Segfault (Code -11)**: The `oaDiskFlusher_rs` module's `py_to_value` function was recursively converting Python dictionaries to Rust/Serde values without depth protection. If a dictionary contained a circular reference (which could be created during in-place metadata updates in the router) or was excessively deep, it would cause a stack overflow and a segmentation fault.
- **SNMP None Error**: `SNMPObserver.handle_protocol_event` attempted to call `.get()` on a `None` value when processing SNMP activity telemetry, leading to an `AttributeError`.
- **Router Signature Mismatch**: `ProtocolRouter._dispatch_loop` was passing individual manager references to `dispatch_message`, which now expects a single `managers` dictionary.

## Resolution
1.  **Updated `oaStateCache/Core/oaDiskFlusher_rs/src/lib.rs`**: Added a recursion depth limit (100) to `py_to_value`. If exceeded, it returns a placeholder string instead of recursing further.
2.  **Updated `oaComSNMP/Managers/snmp_manager.py`**: Added an `isinstance(val, dict)` check before processing SNMP activity monitor messages.
3.  **Updated `oaComBroker/Core/protocol_router/router.py`**: Refactored the `dispatch_message` call to pass a dictionary of all registered transport managers.
4.  **Updated `oaComBroker/Core/protocol_router/ingest.py`**: Added explicit `None` handling and logging during the ingestion phase.

## Verification Evidence
- Modified Rust source code for `DiskFlusher` verified for safety.
- Python syntax verified for all modified files.
- Manual logic trace confirms that `dispatch_message` now receives the correct argument structure.
