# Bug Log: BUG_20260403_213000

## Issue: ProtocolRouter Shutdown Race Condition

**Date**: 2026-04-03
**Severity**: High (Spam in logs, potential data loss during teardown)
**System**: CORE
**Module**: `oaComBroker.Core.protocol_router.router`

### Symptom
During application shutdown, the following error is logged:
`📤🚫🛑 [ERROR] Dispatch Loop Error: cannot schedule new futures after shutdown`
This indicates that the `ProtocolRouter`'s dispatch engine is attempting to process messages after the internal `ThreadPoolExecutor` has been shut down.

### Root Cause
In `ProtocolRouter.stop()`, `self._running` is set to `False` and `self._executor.shutdown(wait=False)` is called immediately. However, the `_dispatch_loop` thread may still be in the middle of an iteration, specifically after retrieving a message from `self.outbound_queue` but before calling `self._executor.submit()`. This small window results in a `RuntimeError`.

### Resolution
Surgically patched `oaComBroker/Core/protocol_router/router.py`:
1.  Added a check for `self._running` immediately before `self._executor.submit()` to catch shutdowns that occur between queue retrieval and task submission.
2.  Implemented a specific `RuntimeError` handler in the `_dispatch_loop` to ignore "after shutdown" errors gracefully, preventing them from being logged as errors during normal teardown.

### Verification
- **Reproduction Script**: `oaTests/Methods/repro_router_crash.py`
- **Result**: Successfully verified that the error is no longer logged during rapid shutdown.
- **System Stability**: Verified that normal message routing remains unaffected.
