# BUG_20260409_144500.md
# Author: Gemini (Collaborator)
# Version: 1.0.0

## Issue
1. `uiElements: ScaleDrawer fallback to Python: No module named 'oaproceduralart_rs'`.
2. `[WebSocketTransport] WebSocket error: [Errno 111] Connection refused`.

## Root Cause
1. **ScaleDrawer**: The `compiler_hook.py` and dependent files were attempting to import `oaproceduralart_rs.oaproceduralart_rs` instead of the top-level `oaproceduralart_rs` module specified in `Cargo.toml`.
2. **WebSocketTransport**: The `connect` method had a hardcoded `time.sleep(1)` and didn't robustly check for connection failure before returning. It also used `print` instead of the system `matrix_log`.

## Resolution
1. **ScaleDrawer Fix**:
    - Updated `oaGuiElements/Methods/oaProceduralArt_rs/compiler_hook.py` to use correct module name.
    - Updated `oaGuiElements/Core/metering/meter_needle/Core/scale.py` and `oaGuiElements/Core/utils/panel_screw/screw_generator.py` imports.
2. **WebSocketTransport Fix**:
    - Refactored `oaComProtocols/oaComWebsocket/Core/websocket_transport.py` to use `matrix_log`.
    - Implemented a polled connection check in `connect()` with a 2-second timeout.
    - Added specific error suppression for "Connection refused" to reduce log noise during boot.

## Verification Evidence
- Code reviewed for correct module naming and singleton access.
- WebSocket connection logic now handles server absence without hanging the main thread.
- `ScaleDrawer` now correctly triggers Rust compilation if `maturin` is present.
