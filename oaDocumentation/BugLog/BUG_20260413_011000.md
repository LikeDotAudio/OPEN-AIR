# Bug Report: 20260413_011000

## Issue
The User Interface and Core services failed to start due to a `ModuleNotFoundError: No module named 'oaRustCore.oa_fast_api_rs'`. This occurred because the `oaComREST` module had a mandatory dependency on a missing Rust binary.

## Root Cause
- `oaComProtocols/oaComREST/Methods/rest_server.py`: Attempted an absolute import of `RustRestServer` from `oaRustCore` without a `try...except` fallback.
- The `RESTManager` initialization (triggered by the `launcher.py` worker) caused a cascading failure across the Core and UI partitions.

## Resolution
- Modified `oaComProtocols/oaComREST/Methods/rest_server.py` to include a `HAS_RUST_REST` flag.
- Implemented a non-crashing `RestServer` class that logs warnings if the Rust binary is missing instead of raising a fatal exception.
- Ensured all methods (`add_route`, `start`) handle the missing `_server` instance gracefully.

## Verification
- Reproduction script `.gemini/TempScripts/repro_rest_bug.py` confirmed that `RestServer` can now be imported and instantiated even when the Rust module is absent.
- System supervisor no longer exits during the protocol manager loading phase.
