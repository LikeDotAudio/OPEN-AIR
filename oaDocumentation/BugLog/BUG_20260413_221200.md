# Bug Log: 20260413_221200

## 1. Research, Clustering & Identification

### Error Clusters:
1. **Cluster 1**: `[OSC] TX Error: OSC Send error: Connection refused (os error 111)`
   - Target: `oaComProtocols.oaComOSC.Workers.osc_tx_client`
   - Trigger: OSC `send_message` failure when target device is offline.
2. **Cluster 2**: `Tkinter Exception: _tkinter.TclError: unknown color name "{'En': 'white', ...}"`
   - Target: `oaGuiElements.Core.metering.meter_bar.Core.config_parser` / `TkCanvasRenderer`
   - Trigger: Tkinter canvas `create_text` drawing when colors are passed as translation dicts.
3. **Cluster 3**: `[REST] Uvicorn failed to start on 0.0.0.0:44935 (SystemExit 1). Port likely in use.` (Warning)
   - Target: `oaComProtocols.oaComREST.Workers.uvicorn_worker`
   - Note: Previously fixed to gracefully warn instead of crash. Working as intended.

### Root Causes:
- **OSC UDP Refused**: The `SimpleUDPClient` relies on socket connectivity. When addressing an unreachable endpoint over UDP, the OS generates an ICMP Port Unreachable error. The python underlying socket throws `ConnectionRefusedError` (os error 111). The OSC client logged every packet failure as a massive error.
- **Tkinter Dictionary Error**: `config_parser.py` was pulling color strings out of nested translation dicts but failing to pass them through the `get_text` utility. When passed down the chain, `Tkinter` rejected the raw python `dict` object passed as a color hex/name.

---

## 2. Plan of Action

1. **Fix UI Dictionary parsing**: Wrap all color fields extracted from configuration layouts in `config_parser.py` with the `get_text` hook.
2. **Throttle OSC Connection Refusals**: Enhance `osc_tx_client.py`'s `send_message` block. Identify "connection refused" text exceptions and apply a 5-second `osc_logger.warning()` throttle to prevent log file spamming.
