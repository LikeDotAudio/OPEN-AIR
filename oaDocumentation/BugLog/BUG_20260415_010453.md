# Bug Report - 20260415_010453

## Issue 1: `EmberManager.init()` unexpected keyword argument 'state_cache_manager'

### Description
The `EmberManager` in `oaComProtocols/oaComEmber/Entry.py` was not correctly initialized in its `__init__` method, leading to a `TypeError` when `test_ember_manager.py` attempted to pass `state_cache_manager` as an argument. The existing `EmberManager` definition in `Entry.py` was a placeholder and did not include this expected argument in its constructor signature.

### Root Cause
The `EmberManager.__init__` method did not declare `state_cache_manager` as an accepted argument, while the test suite `test_ember_manager.py` was designed to provide it.

### Resolution
Modified `oaComProtocols/oaComEmber/Entry.py` to include `state_cache_manager=None` in the `EmberManager.__init__` method signature and assigned it as a class instance variable. This aligns the manager's interface with the test's expectations and potential future requirements for state management.

### Verification
The `oaComProtocols/oaComEmber/Tests/test_ember_manager.py` suite now passes all tests, confirming that `EmberManager` can be instantiated correctly with the `state_cache_manager` argument.

## Issue 2: `NMOSManager` `test_standardized_lifecycle` failure (running state after stop)

### Description
The `test_standardized_lifecycle` in `oaComProtocols/oaComNmos/Tests/test_nmos_manager.py` failed because the `NMOSManager`'s `status()["running"]` returned `True` even after the `stop()` function was called. This indicated that the `stop()` function was not correctly updating the module's internal running state.

### Root Cause
The `stop()` function in `oaComProtocols/oaComNmos/Entry.py` was responsible for stopping the `_bridge_manager` but did not explicitly set the `global_state["RUNNING"]` flag to `False`. As a result, the `status()` function, which relies on `global_state["RUNNING"]`, continued to report the module as running.

### Resolution
Modified `oaComProtocols/oaComNmos/Entry.py` to add `global_state["RUNNING"] = False` within the `stop()` function. This ensures that the global state accurately reflects the stopped status of the NMOS module.

### Verification
The `oaComProtocols/oaComNmos/Tests/test_nmos_manager.py` suite now passes all tests, specifically the `test_standardized_lifecycle` test, confirming that the `NMOSManager` correctly reports its stopped state after the `stop()` function is invoked.
