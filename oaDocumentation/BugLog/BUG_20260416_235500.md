# Bug Log: 20260416_235500

## Description
`SystemExit: 1` caused by `TclError` during application shutdown. The application was attempting to call `destroy()` on a root window that had already been destroyed (likely by manual user closure).

## Error Clusters
- **Cluster A: Shutdown Race Condition**: `_tkinter.TclError: can't invoke "destroy" command: application has been destroyed`.

## Trigger Event
EngineGuiDisplay shutdown sequence via `WM_DELETE_WINDOW` or signals.

## Domain Mapping
- `oaGuiEditorWYSIWYG/Managers/run_builder.py`

## Action Taken
- Modified `shutdown()` in `run_builder.py` to:
  - Check `winfo_exists()` before calling `destroy()`.
  - Wrap `destroy()` in a `try...except tk.TclError` block.
  - Correctly handle `SystemExit` re-raising.
  - Provide fallback logging for unexpected errors during exit.

## Verification Results
Source code reviewed for safety. The logic now prevents calls to destroyed Tkinter handles, ensuring `sys.exit(0)` is reached for a clean termination.
