# BUG LOG: Performance & Resource Optimization (2026-05-05)

## 🕵️ Forensic Summary
Following a Performance & Resource Audit, three systemic inefficiencies were identified and resolved to improve system stability, UX, and memory safety.

## 📋 Resolved Tasks

### 1. Adaptive State Restoration [CORE/STATE]
- **Issue**: Linear 2ms delay per topic during state replay caused significant startup latency and potential main-thread lockups.
- **Fix**: Refactored `restore_timeline` in `gui_state_restorer.py` to use a "Batch & Yield" strategy.
- **Result**: GUI remains responsive during boot; restoration speed is increased by batching 50 topics per frame.

### 2. VISA Memory Guard & Log Truncation [COMMS/VISA]
- **Issue**: Unbounded reading of instrument buffers and full-payload logging of large binary responses.
- **Fix**: Updated `visa_safe_query.py` to monitor buffer size (>1MB warning) and enforced Mandate 19 (100-char truncation) on response logs.
- **Result**: Prevents memory spikes and terminal flooding during waveform captures.

### 3. MIDI/MQTT Batch Publication [UI/MIDI]
- **Issue**: N+1 publication pattern when sending MIDI events across multiple channels.
- **Fix**: Implemented `publish_batch` in `MqttConnectionManager` and `MidiManager`. Refactored `MidiOutputGenerator` to use the batch API.
- **Result**: Reduced network context switching and thread-safe queue overhead for multi-channel MIDI automation.
