Bug Report: Composite Widget Crash, Graphing Errors, and Asset Loading Failures

Issue

  1. EngineGuiDisplay crash when loading _VUMeterKnob due to AttributeError.
  2. Graphing components (DynamicGraph, DynamicBarGraph) failed to render with "Unknown functional widget" errors.
  3. Animations failed to load with "GIF not found" errors.
  4. ProgressBar threw registry warnings about a missing make method.

Root Cause Analysis

  1. Composite Crash: BuilderMeterKnobWithVuMeterCreator was attempting to call self.make_meter_needle directly on the builder instance. In the modular architecture, this method is no longer present on the builder and must be called via the specialized creator class. Additionally, _NeedleVUMeter was not registered with the RegistryWidgetStore.
  2. Missing Graphs: The factory_mapping.py was missing the lazy-wrapper entries for several graphing widget aliases used in JSON configurations.
  3. Asset Mismatch: JSON definitions for animations were pointing to a non-existent directory oaDataCache/assets/images/, while the actual assets were located in oaGui/Assets/.
  4. Registry Inconsistency: BuilderImagesProgressBarCreator was registered but lacked the standard static make method required by the new factory pattern.

Resolutions

  1. Composite Fix:
    • Registered BuilderMeterNeedleCreator with _NeedleVUMeter.
    • Updated BuilderMeterKnobWithVuMeterCreator to use BuilderMeterNeedleCreator.make() and BuilderKnobCreator.make() instead of instance method calls.
  2. Factory Mapping: Added plot_widget, bar_graph, _GuiGraph, DynamicGraph, and DynamicBarGraph to oaGui/Core/factory/Core/factory_mapping.py.
  3. Asset Correction: Batch-updated JSON paths for time_circuits.gif using sed.
  4. Interface Alignment: Added the static make method to BuilderImagesProgressBarCreator.
