Bug Log: BUG_20260312_004500

<strong>Issue</strong>

User Analysis: "the system is getting trapped in the echo chamber... cache restoration wakes up and reads the saved state from disk. It floods the MQTT broker... Both partitions independently preparing to settle the exact same parameters at the exact same time... infinite ping-pong." Problem: Competing partitions (CORE and UI) were both starting settling timers for the same external events, leading to a feedback loop where each partition's "settled" broadcast triggered the other to re-settle. Additionally, the Panic protocol crashed the MQTT publisher with raw dictionary payloads.

<strong>Root Cause</strong>

  1. Non-Terminal Feedback: ProtocolRouter.ingest triggered a _schedule_settling timer for any message passing the local loop prevention, regardless of whether it was a control "Action" or a state "Feedback".
  2. Publisher TypeError: aiomqtt (or the underlying paho-mqtt client) expects strings or bytes for payloads. The SplinkerManager._handle_panic method was passing a raw Python dictionary, causing a fatal error in the publishing worker.

<strong>Investigation</strong>

  1. Log Analysis: Verified in Application_20260312_0040.log that both partitions were firing "⏳ Settling" messages for the same topics repeatedly.
  2. Code Review: Confirmed ProtocolRouter.ingest did not distinguish between msg_type for the purpose of starting the settling timer.

<strong>Resolution</strong>

  1. Terminal Settling: Modified ProtocolRouter.ingest to strictly suppress the settling timer for LINK_FEEDBACK messages. Only SPLICE_ACTION (original movements) can now trigger a settling cycle.
  2. Panic Payload Hardening: Updated SplinkerManager._handle_panic and _reset_panic to explicitly serialize dictionary payloads using orjson.dumps().decode() before passing them to the MQTT manager.

<strong>Verification</strong>

  1. Unit Test: reproduce_settling_loop.py confirmed that receiving a LINK_FEEDBACK message no longer triggers a "Settling: Firing final LINK_FEEDBACK" log entry.
  2. System Stability: Confirmed that Panic triggers no longer crash the publisher worker.
  3. Trace Verification: Observed that cache restoration (origin: DISK) now completes visuals without triggering infinite MQTT re-broadcasts between CORE and UI.
