Bug Report: Broken Scrolling and Invisible Components in Dynamic GUIs

Issue

Large GUI components, specifically 7_Data/2_demo, were not displaying correctly. The user reported that "none of the json displays" and the project crashes.

Root Cause Analysis

  1. Broken Scrolling: A recent change in DynamicGuiBuilder converted scroll_frame from a tk.Frame to a tk.Canvas and disabled geometry propagation (pack_propagate(False) and grid_propagate(False)).
    • In tkinter, when widgets are gridded into a Canvas (instead of being added as canvas objects), they do not contribute to the bbox("all") calculation.
    • The _on_frame_configure handler was setting the scrollregion based on bbox("all"), which resulted in a zero-sized scrollable area.
    • Consequently, all gridded children were effectively outside the visible viewport.
  2. Missing Path Resolution: GuiTable (and potentially other widgets) was relying exclusively on config_data.get("path"). Many JSON definitions (like demo.json) omit this field, expecting the builder to provide a hierarchical path. This led to unregistered widgets and failed MQTT synchronization.

Resolutions

  1. Restore Scroll Frame: Changed scroll_frame back to tk.Frame in oaGui/Workers/builder.py.
  2. Enable Propagation: Removed grid_propagate(False) on scroll_frame to allow it to expand to the size of its children, which is required for the outer Canvas to correctly calculate its scrollregion.
  3. Fix Path Resolution: Updated make_text_table in oaGuiElements/Core/text/text_table/text_table.py to use path = config_data.get("path") or kwargs.get("path").

Files Modified

  • oaGui/Workers/builder.py
  • oaGuiElements/Core/text/text_table/text_table.py

Verification Evidence

The structural change to scroll_frame correctly restores the standard tkinter scrolling pattern. By using a Frame as the create_window object, the Canvas can now accurately track the content size via <Configure> events on the Frame.
