Bug Report: UI Initialization Crash (X11 BadValue)

Date: 2026-04-04 Time: 22:50:00 Module: oaGui.Interface.ui_window, oaGuiBuildShell.Core.directory Priority: 1 (Critical/Crash)

Issue

The UI partition would crash on Linux with an X11 error: X Error of failed request: BadValue (integer parameter out of range for operation) Major opcode 12 (X_ConfigureWindow) Value 0x0. This typically occurred shortly after the splash screen appeared and the workspace build began.

Root Cause

  1. Premature Maximization: The root window was being maximized (-zoomed) while in a withdrawn state. On certain Linux window managers/X11 backends, this causes a deferred BadValue error when the system tries to calculate or apply dimensions.
  2. Aggressive Event Processing: The use of root.update() during the recursive build process forced synchronous X11 communication while windows and widgets were in transient states (unmapped, 0-dimension parents).

Resolution

  1. Deferred Maximization: Refactored UIWindowManager to move the maximization logic from create_root_window (where it was withdrawn) to reveal_main_window (where it is deiconified).
  2. Safer Event Loops: Replaced all instances of root.update() in DirectoryBuilderMixin and AsyncBootstrapEngine with root.update_idletasks(). This ensures the UI remains responsive for geometry/layout updates without forcing potentially invalid X11 configurations during the build.

Verification Evidence

  1. Unit Tests: test_ui_window.py and test_bootstrap_sequence.py passed, confirming correct logic flow and successful service initialization.
  2. Refined UI Sequence: The logs now correctly show the sequence of events without triggering X11 exceptions during the background build.

Status: Fixed & Verified.
