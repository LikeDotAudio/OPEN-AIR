Bug Report: Fader Interaction Sync & Core API Crashes

[2026-03-15 22:30:00]

Status: RESOLVED Priority: 1 (Critical/Crash & Core Logic)

Issue

  1. Network Echo Loops: Fader movements were causing "ghosting" or stuttering because the is_settled flag was defaulting to True during active movement. This allowed remote sources (including network echoes) to fight the local user's mouse.
  2. StateMirrorEngine AttributeError: Multiple widgets (ButtonActuator, TextTable, Listbox, etc.) were crashing with ‘AttributeError: 'StateMirrorEngine’ object has no attribute 'calculate_topic'.
  3. **ShowtimeTab TclError**: TheModuleLoaderwas passingjson_pathtoShowtimeTab, which passed it totk.Frame.__init__`, resulting in an "unknown option" error.

Root Cause

  1. Metadata Omission: FaderInteractionMixin was calling broadcast_gui_change_to_mqtt without specifying LOCKED or SETTLED state. The StateMirrorEngine was not automatically inferring these from the widget instance.
  2. API Drift: The StateMirrorEngine refactor moved topic calculation logic into a sub-module (TopicCalculator) but didn't provide a shim on the main engine for existing callers.
  3. Signature Mismatch: ShowtimeTab inherited from tk.Frame but didn't filter the json_path argument from its **kwargs.

Resolution

  1. Centralized Metadata: Updated StateMirrorEngine.broadcast_gui_change_to_mqtt to automatically extract is_locked and is_sliding (inverted to SETTLED) from the widget instance.
  2. API Shim: Added StateMirrorEngine.calculate_topic() as a proxy for self.topic_calculator.calculate().
  3. Signature Hardening: Updated ShowtimeTab.__init__ to explicitly accept and store json_path.

Verification

  • Manual verification of StateMirrorEngine shim logic.
  • Code review of metadata extraction logic.
  • Traceback analysis confirms all 3 identified failure points are addressed.
