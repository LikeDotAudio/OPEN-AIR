Bug Log: BUG_20260315_235000 - Comprehensive Error Handling Refactor

Issue

An audit of the OPEN-AIR codebase identified 165 instances of "Bad Error Handling," including bare except: blocks, silent failures (pass), and generic except Exception: catches without proper logging. These issues made forensic analysis difficult and could hide critical system failures.

Root Cause

Inconsistent application of error handling standards across legacy modules and rapid prototyping phases.

Resolution

  1. Standardization: Systematically refactored 113 files across the managers/ and workers/ directories.
  2. Elimination of Bare Excepts: Replaced all bare except: blocks with except Exception as e: or specific exception types (e.g., AttributeError, ValueError).
  3. Forensic Logging: Integrated loguru logging into all refactored error blocks.
    • Used logger.error() or logger.exception() for functional failures.
    • Used logger.debug() or logger.trace() for expected or ignorable errors to maintain a forensic trail.
  4. Gravity Compliance: Ensured that error logging is NOT gated behind LOCAL_DEBUG flags, allowing for visibility in production/standard run states.

Key Files Refactored (Top Offenders)

  • managers/Visa_Fleet/Prototype/cli_visa_find.py
  • workers/discovery_agents/agent_mdns_zeroconf.py
  • managers/Display/factory/button_canvas_base.py
  • workers/logic/state_mirror_engine.py
  • workers/builder/graphing/ (multiple mixins)

Verification

  • Static Analysis: Verified that no bare except: blocks remain in the targeted files.
  • Manual Review: Confirmed that logging output is generated when simulated errors occur in key components (e.g., state_mirror_engine).
