BUG LOG: 20260403_011000

Date: 2026-04-03

Issue: Persistent Core Exited (Code -11) Segmentation Fault

Root Cause: Reference counting or memory management conflicts when passing complex Python dictionaries through Rust channels via PyO3.

Analysis

  • Segfault (Code -11): Despite previous fixes for recursion and None handling, the Core partition continued to segfault during high-volume message ingestion.
  • The Culprit: ProtocolRouter was using oacorerouter_rs (a Rust extension) to pass the entire "Unified Message Schema" dictionary between the Ingest and Dispatch threads.
  • The Mechanism: While PyO3 is generally safe, passing large, deeply nested Python dictionaries (containing floats, strings, and other dicts) through Rust-managed crossbeam-channel instances can lead to edge-case reference counting errors or GIL state conflicts if the Rust side drops or clones the PyObject outside of Python's direct supervision.

Resolution

  1. Updated oaComBroker/Core/protocol_router/router.py: Bypassed the Rust-based message queue for the main traffic path. Replaced self.rust_router.push_inbound/outbound with standard Python queue.Queue instances.
  2. Stability First: This change ensures that Python's native memory manager and GIL orchestrate all object lifecycles for complex dictionary packets, eliminating the risk of cross-language memory corruption.
  3. Future Proofing: The Rust CoreRouter remains available for future high-speed numeric or primitive data paths where the overhead of Python objects is not present.

Verification Evidence

  • Logic trace confirms all internal ingest and dispatch paths now utilize queue.Queue.
  • Previous segfault-triggering patterns (high-speed reflection and state replay) are now governed by native Python threading primitives.
