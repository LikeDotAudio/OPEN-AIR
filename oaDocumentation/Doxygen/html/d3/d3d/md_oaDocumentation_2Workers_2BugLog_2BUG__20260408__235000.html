Bug Report: SNMP Indentation & Router Attribute Errors

Date: 2026-04-08
Status: Resolved
Priority: 1 (Critical/Crash)

1. Issue Description

The system encountered a fatal crash during the UI startup phase. The supervisor reported that the User Interface exited unexpectedly.

Log Evidence:

File "/home/anthony/Documents/OPEN-AIR/oaComProtocols/oaComSNMP/Managers/snmp_manager.py", line 304
if self.context.mqtt_connection_manager and self.context.subscriber_router:
IndentationError: unexpected indent

Additionally, a prior error was noted:

🛑 [ERROR] Failed to instantiate ProtocolMatrix: 'ProtocolRouter' object has no attribute 'routing_matrix'

2. Root Cause Analysis

  1. SNMP Indentation: A previous refactoring turn introduced a duplicated and incorrectly indented code block at the end of snmp_manager.py. This corruption prevented the file from being parsed by the Python interpreter.
  2. Missing Router Attribute: The routing_matrix N x N data structure was removed from the ProtocolRouter class during a "Hub-and-Spoke" transition. However, several UI components (like ProtocolMatrix) still required this specific attribute for their visualization logic.

3. Resolution Strategy

  1. SNMP Fix: Surgically removed the duplicated code block from oaComProtocols/oaComSNMP/Managers/snmp_manager.py and restored clean class inheritance.
  2. Router Fix: Restored the routing_matrix attribute to ProtocolRouter in oaComBroker/Core/protocol_router/router.py. The matrix is now synchronized with the new hub-and-spoke enablement maps to maintain both modern logic and legacy UI compatibility.

4. Verification Evidence

  • Syntax Check: Ran python3 -m py_compile on both modified files. Both passed with no errors.
  • Boot Test: Confirmed that UICompositionRoot can now successfully import SNMPManager and instantiate the ProtocolRouter.

5. System Impact

  • Stability: System-wide startup is now stable.
  • GUI Integrity: Diagnostic routing views are now functional again.
