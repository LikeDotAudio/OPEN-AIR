Bug Report: BUG_20260330_013000

Issue

The oaComProtocols.oaComOSC module was emitting high-velocity debug logs (Heartbeats, RX/TX traffic) that were difficult to silence because they used static LOCAL_DEBUG flags initialized at module load.

Root Cause

  1. Static Initialization: LOCAL_DEBUG was set once when the module was first imported, meaning changes to config.ini required a full application restart to take effect.
  2. Ungated Logs: Several logs in the OSC manager and workers were either ungated or used the static flag.

Resolution

  1. Dynamic Gating: Refactored oaComProtocols.oaComOSC/Managers/osc_manager.py, oaComProtocols.oaComOSC/Workers/osc_rx_server.py, and oaComProtocols.oaComOSC/Workers/osc_tx_client.py to use a dynamic _is_debug() function.
  2. Matrix Integration: The new _is_debug() function calls is_debug_allowed(system="UI", element="OSC"), which queries the live LoggingMatrixManager.
  3. Real-time Response: Debugging for the entire OSC system can now be toggled on/off instantly via the config.ini or the Test TUI without restarting the process.

Verification

  1. Manual code audit confirms all logger.debug and logger.success calls in the OSC module are now gated by if _is_debug():.
  2. Verified that setting ELEMENT_OSC = False in the Debug Matrix successfully silences the traffic logs while allowing other system logs to persist.
