Bug Report - 2026-04-02 23:00:00

Issues

This report details the resolution of a critical NameError in the state cache and the fixing of multiple Rust build failures that were preventing graceful degradation.

Root Causes & Resolutions

1. NameError in StateRegistry

  • Issue: ‘NameError: name 'MqttMessage’ is not definedinoaStateCache/Core/state_cache.py.
  • **Root Cause**: During the implementation of the "Graceful Rust Failure" pattern in a previous turn, several critical imports (includingMqttMessage,Config, and core engine references) were inadvertently removed. This caused the UI partition to crash during the class definition phase ofStateRegistry.
  • **Resolution**: Restored all missing imports and global variable initializations inoaStateCache/Core/state_cache.py`.

2. Rust Build Failures (Missing README)

  • Issue: maturin failed: Failed to read readme specified in pyproject.toml.
  • Root Cause: The pyproject.toml files for oaAsyncSink_rs and oaClockSync_rs explicitly required a README.md file that did not exist in their respective directories. This caused the background compilation process to fail with a non-zero exit status.
  • Resolution: Created standardized placeholder README.md files in:
    • oaLogging/Core/oaAsyncSink_rs/README.md
    • oaWatchdog/Methods/oaClockSync_rs/README.md

3. Fragile Logging in Graceful Fallbacks

  • Issue: Potential NameError during the "except" block of Rust imports.
  • Root Cause: Several files (ptp_packet_parser.py, blueprint_loader.py, yak_translator.py, visa_Search.py) were attempting to log warnings about missing Rust modules using logger or logging before those names were actually imported into the module namespace.
  • Resolution: Adjusted the import order in all affected files to ensure that logging utilities are available before any try...except blocks that might require them.

Affected Modules

  • oaStateCache (StateRegistry crash fixed)
  • oaLogging (Build failure fixed)
  • oaWatchdog (Build failure fixed)
  • oaPTP (Graceful failure logging fixed)
  • oaGui (Graceful failure logging fixed)
  • oaTranslator (Graceful failure logging fixed)
  • oaComProtocols.oaComVisa (Graceful failure logging fixed)

Verification

The system now correctly handles the absence of Rust modules by logging a warning and continuing the boot process. The UI partition no longer crashes due to missing type definitions, and the background build system successfully processes all crates.
