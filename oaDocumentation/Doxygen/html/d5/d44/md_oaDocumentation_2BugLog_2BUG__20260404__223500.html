Bug Report: Noisy Traceback for Missing Blueprints

Date: 2026-04-04 Time: 22:35:00 Module: oaGui.Core.loader.gui_from_json Priority: 2 (High/Spam)

Issue

When a GUI blueprint (JSON file) was missing, the UniversalGuiLoader would log a full traceback using logger.exception. While the error was correctly handled by transitioning the UI to an error state, the verbose traceback in the logs was confusing and cluttered CI/CD output, appearing as an unhandled crash.

Root Cause

The _construct_dynamic_gui method used a generic except Exception block with logger.exception to catch all errors during the build process. FileNotFoundError (raised when a blueprint is missing) fell into this block, triggering a full stack trace.

Resolution

Refactored the try...except block to explicitly catch FileNotFoundError.

  • FileNotFoundError is now logged as a standard logger.error (no traceback).
  • Exception remains as a fallback for unexpected catastrophic failures, preserving the full traceback for debugging.

Verification Evidence

Verified with a reproduction script (.gemini/TempScripts/reproduce_bug.py):

  1. Missing Blueprint: Logs a single line: ❌ Blueprint missing! Module: ... | Path: ...
  2. Unexpected Error (RuntimeError): Still logs the full 💥 The Flux Capacitocracked... message with a traceback.

Status: Fixed & Verified.
