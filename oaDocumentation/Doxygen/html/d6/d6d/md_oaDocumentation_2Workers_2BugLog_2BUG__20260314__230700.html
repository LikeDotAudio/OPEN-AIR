Bug Report: Missing MQTT Announcements for GUI Changes

Date: 2026-03-14 23:07:00
Priority: 1 (Critical - Functional regression)
Status: Resolved
Module: workers/logic/state_mirror_engine.py

Issue

GUI changes performed by the user (e.g., turning a knob, sliding a fader) were intermittently failing to produce MQTT event announcements. This resulted in other parts of the system and external MQTT monitors not receiving state updates from the UI.

Root Cause

The StateMirrorEngine relied on individual widget creators to manually invoke broadcast_gui_change_to_mqtt() within their specific event handlers (click, drag, release). Several newer or refactored widgets lacked these manual calls, and others only triggered the broadcast on 'release', causing 'real-time' tracking to fail.

Furthermore, any programmatic updates to the underlying Tkinter variables (e.g., from custom macro logic) were not being broadcast at all.

Resolution

Modified StateMirrorEngine.register_widget to automatically attach a trace_add("write", ...) callback to every registered Tkinter variable. This ensures that any change to a registered variable (whether from user interaction or internal logic) is automatically evaluated and broadcast to the MQTT bus, provided it passes the engine's built-in throttling and loop-prevention checks.

Verification Evidence

  1. Reproduction: A script reproduce_mqtt_issue.py was created to register a variable with the engine and verify that var.set() did NOT trigger a call to the StateCacheManager or the MQTT publisher.
  2. Fix Verification: The same script now confirms that var.set() triggers a successful MQTT broadcast via the automatic trace mechanism.
  3. Robustness: The fix correctly respects _silent_update and _binding_suspended flags to prevent recursive feedback loops during remote sync or startup.

Impact

Ensures 100% reliable state synchronization between the GUI and the MQTT network for all widget types across the entire application.
