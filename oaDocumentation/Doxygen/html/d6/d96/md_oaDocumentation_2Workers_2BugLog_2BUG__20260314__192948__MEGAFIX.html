BUG: Comprehensive GUI Layout & Builder System Overhaul

  • ID: 20260314_192948
  • STATUS: RESOLVED
  • SEVERITY: 1 (Critical)
  • COMPONENT: managers/Display/loader/gui_from_json, managers/Display/builder/async_grid_renderer, workers/builder/builder

Issue

A series of related bugs in the GUI loading and rendering pipeline were causing a cascade of failures, including partially rendered UIs, incorrect layouts, non-expanding containers, and non-functional debug features. The user reported that top-level GUI containers (OcaBin) were not filling the screen, and that the debug "structure boxes" were not appearing.

Root Cause Analysis

The investigation revealed a chain of interacting bugs across the entire GUI builder stack:

  1. Top-Level Container Sizing Failure: The UniversalGuiLoader class, responsible for loading JSON-based GUIs, was not configured to allow its child widget (the DynamicGuiBuilder) to expand. It was missing the necessary grid_rowconfigure and grid_columnconfigure calls, causing its child to be placed in a fixed-size cell and resulting in the "half-rendered screen" effect.
  2. Inconsistent Geometry Managers: The DynamicGuiBuilder used .pack() to place its main content frame, while the AsyncGridRenderer used .grid() to place widgets inside it. This mixing of geometry managers is notoriously problematic in Tkinter and leads to unpredictable sizing behavior.
  3. Missing Debug Feature: The AsyncGridRenderer's logic for processing OcaBlock widgets had no implementation for drawing the visual debug outlines, even though the feature was exposed in the UI.

Resolution

A comprehensive, multi-part fix was applied across the GUI stack to resolve these issues and harden the rendering pipeline.

  1. **DynamicGuiBuilder Flexibility (workers/builder/builder.py)**:
    • A use_grid parameter was added to the __init__ method. When True, this prevents the builder from automatically calling .pack(), allowing the parent class to manage its geometry.
    • The builder's internal layout was modified to use .grid() exclusively, eliminating the conflict between .pack() and .grid().
  2. **UniversalGuiLoader Fix (managers/Display/loader/gui_from_json.py)**:
    • The loader now configures its own grid with self.grid_rowconfigure(0, weight=1) and self.grid_columnconfigure(0, weight=1).
    • It now instantiates DynamicGuiBuilder with use_grid=True and places it correctly using .grid(row=0, column=0, sticky="nsew"). This ensures the top-level GUI container expands to fill its allocated pane.
  3. **Debug "Structure Box" Fix (managers/Display/builder/async_grid_renderer.py)**:
    • The logic for rendering an OcaBlock was updated. It now checks if the builder's show_structure flag is set and, if so, configures the block's canvas with a red highlightbackground to make the structure visible.

This series of fixes ensures that the entire chain, from loading a JSON file to rendering its deepest nested widgets, uses a consistent geometry management system and correctly propagates size requirements, while also restoring a key debug feature.

Verification

The application GUI now renders completely and correctly. Top-level OcaBin containers expand to fill their panes. Complex nested layouts with multiple rows and columns expand both vertically and horizontally. The "Show Structure" debug feature now correctly draws red outlines around OcaBlock containers.
