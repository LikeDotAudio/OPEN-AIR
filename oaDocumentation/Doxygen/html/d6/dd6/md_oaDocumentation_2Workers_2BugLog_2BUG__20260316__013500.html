Bug Report: Component Registration and Graphing Import Failures

Date: 2026-03-16 01:35:00 Priority: 1 (Critical/Crash) Impact: UI rendering failures for complex layouts (Spectrum, Master Bin) and inefficient hardware discovery.

Issue

  1. AttributeError: ‘module 'hidden_BreakLine’ has no attribute 'BuilderBreakLineCreator'triggered when attempting to renderOcaFoldwidgets.
  2. **ModuleNotFoundError**:No module named 'oaGui.graphing'in graphing mixins after the widget migration.
  3. **Performance/Stability**:IDN Query Errorand slow probing inVisa_Fleet` due to redundant system calls.

Root Cause

  1. Improper Mapping: factory_mapping.py was manually overwriting the RegistryWidgetStore with an incorrect string-based reference to a class that wasn't yet properly implemented as a Creator.
  2. Stale Imports: graph_throttle_mixin.py and graph_patina_mixin.py were missed during the initial automated import update for the graphing migration.
  3. Over-defensive Probing: VisaUtilityParser.query_device_safe was calling rm.list_resources() on every single device probe, which is an extremely expensive blocking operation.

Resolution

  1. Corrected OcaFold: Fully implemented BuilderBreakLineCreator in hidden_BreakLine.py and removed the redundant manual entry from factory_mapping.py.
  2. Updated Graphing Imports: Manually corrected the graph_updater import paths in the affected mixins.
  3. Optimized VISA Probing:
    • Removed list_resources() from the hot path.
    • Wrapped PyVISA open_resource and query in robust try-except blocks.
    • Ensured resources are always closed via finally blocks.

Verification

  • Registry Test: Confirmed via script that OcaFold, plot_widget, and bar_graph are correctly registered in the RegistryWidgetStore.
  • Import Test: Confirmed LoaderOrchestrator and its mixins load without ModuleNotFoundError.
