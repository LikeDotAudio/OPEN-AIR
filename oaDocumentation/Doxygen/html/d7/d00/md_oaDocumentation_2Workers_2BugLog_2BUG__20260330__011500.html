Bug Report: BUG_20260330_011500

Issue

Developers lacked a convenient way to launch and terminate the main openair.py system directly from the oaTests suite during maintenance or testing cycles.

Resolution

  1. UI Integration: Added a "Process Controls" bar to the top of the CenterPanel in oaTests/Interface/center_panel.py.
  2. Process Management: Implemented perform_start_openair and perform_stop_openair logic in TestsUI.py using subprocess.Popen and process group management (os.setsid).
  3. Visual Feedback: Buttons provide immediate visual confirmation of process status via the central execution log.

Verification

  1. Manual UI audit confirms "START OPEN-AIR" and "STOP OPEN-AIR" buttons are correctly rendered and styled.
  2. Verified that "START" correctly spawns the multi-partition supervisor and logs the PID.
  3. Verified that "STOP" successfully terminates the entire process group (including UI and Core partitions) without leaving zombie processes.
