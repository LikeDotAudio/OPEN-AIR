BUG: PanedWindow Layout Percentages Not Respected

  • ID: 20260314_183952
  • STATUS: RESOLVED
  • SEVERITY: 2 (High)
  • COMPONENT: oaGuiBuild.Managers.gui_display

Issue

The GUI was not correctly applying percentage-based layouts for ttk.PanedWindow widgets as defined by directory naming conventions (e.g., top_10, bottom_90). Instead of splitting the view into a 10/90 ratio, the UI defaulted to an equal 50/50 split. This indicated that while the layout type (vertical split) was being correctly identified, the proportions were being ignored.

Root Cause Analysis

The _build_from_directory method in gui_display.py is responsible for creating the ttk.PanedWindow when it receives a horizontal_split or vertical_split layout type from the parser. While the parser correctly extracted the percentage values (10 and 90) into a weight key for each panel, the builder was not using these weights to manually position the sash.

The ttk.PanedWindow widget does not automatically distribute space based on the weight parameter of the .add() method in the way one might expect for pixel-perfect ratios. To enforce specific proportional sizes, one must manually calculate and set the position of the sash(es) using the .sashpos() method after the window has been drawn and sized.

The logic to do this was missing. A previous refactoring had removed the configure_sash inner function that was responsible for this crucial step.

Resolution

The sash positioning logic was restored within the _build_from_directory method for split-pane layouts.

  1. **configure_sash Re-implemented**: A nested function, configure_sash(event=None), was added back into the horizontal_split/vertical_split block.
  2. Proportional Calculation: Inside this function, it calculates the total weight of all panels. It then iterates through the panels and calculates the exact pixel position for each sash based on the panel's weight relative to the total weight and the current width or height of the PanedWindow.
  3. Manual Sash Positioning: It uses paned_window.sashpos(i, int(cumulative_size)) to manually move the sash to the calculated position.
  4. Event Binding: The configure_sash function was bound to the paned window's <Configure> event. This ensures that whenever the window is resized, the sash positions are recalculated and reapplied, maintaining the correct proportions.
  5. Initial Positioning: An self.after(50, configure_sash) call was added to trigger an initial positioning shortly after the widget is first created, ensuring the correct layout appears on the first render.

This change ensures that the percentage values parsed from directory names are now correctly translated into visual proportions on the screen.

Verification

The UI now correctly renders the top_10 and bottom_90 directories as a 10/90 vertical split. Resizing the main window correctly maintains this ratio. All directory-based split-pane layouts are now being rendered with their intended proportions.
