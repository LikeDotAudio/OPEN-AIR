BUG: OcaBin Container Not Expanding Vertically

  • ID: 20260314_192214
  • STATUS: RESOLVED
  • SEVERITY: 2 (High)
  • COMPONENT: oaGuiBuild.async_grid_renderer

Issue

GUI layouts built from JSON files using the OcaBin container type were not rendering correctly. The container would only occupy a small portion of the vertical space in its parent frame, typically resulting in the UI looking "squashed" or "only half rendered," even when configured with "anchor": "NSEW".

Root Cause Analysis

The issue was traced to the render method in the AsyncGridRenderer class. This method is the primary entry point for constructing GUI elements from a JSON blueprint.

The code correctly iterated through the specified layout_columns and configured the parent frame's columns using parent_frame.grid_columnconfigure(col_idx, weight=1). This allowed child widgets to expand horizontally.

However, the equivalent configuration for the rows was completely missing. There was no corresponding parent_frame.grid_rowconfigure() call. In the Tkinter grid system, for a child widget to expand and fill its cell (using sticky="nsew"), both the column and the row it occupies must have a non-zero weight. Because the row weight was 0 (the default), the OcaBin container was placed in a row that would not expand vertically, regardless of its own settings.

Resolution

The fix was to add the missing row configuration to the render method in async_grid_renderer.py.

  1. A new line, parent_frame.grid_rowconfigure(0, weight=1), was added just before the column configuration loop.

This simple addition ensures that the primary row (row 0) of the parent container is configured to expand vertically. When the OcaBin (or any other widget) is placed in this row with sticky="nsew", it now correctly stretches to fill the entire available vertical space, resolving the rendering issue. This fix assumes a simple, single-row layout within the OcaBin's parent, which aligns with its usage as a primary content container.

Verification

After the fix, all GUI elements defined within an OcaBin container now correctly expand to fill the entire vertical and horizontal space allocated by their parent widget. The "half-rendered" appearance is gone, and the UI layout now behaves as specified in the JSON configuration files.
