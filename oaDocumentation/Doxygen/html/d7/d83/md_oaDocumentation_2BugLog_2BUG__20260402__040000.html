Bug Report - 2026-04-02 04:00:00

Issues

This report details the resolution of a ModuleNotFoundError for compiler_hook in the oaPTP module and the alignment of its Rust extensions with the project's absolute import standard.

Root Causes & Resolutions

1. ModuleNotFoundError: 'compiler_hook' in PTPPacketParser

  • Issue: ‘ModuleNotFoundError: No module named 'compiler_hook’inoaPTP/Core/ptp_packet_parser.py.
  • **Root Cause**: The code was using a hackysys.pathmodification to import a localcompiler_hook.pyfile, but the path was hardcoded with a hyphen (oaPtpParser-rs) while the actual directory used an underscore (oaPtpParser_rs).
  • **Resolution**: Replaced thesys.pathhack with a standard absolute import:from oaPTP.Methods.oaPtpParser_rs import compiler_hook`.

2. Relative Import Failures in PtpClock

  • Issue: Potential loading failures for oaptpclock_rs due to relative import path usage.
  • Root Cause: The module was attempting to import its Rust extension using a relative path that did not match the top-level installation performed by maturin develop.
  • Resolution: Updated oaPTP/Methods/ptp_clock.py to use an absolute import for the compiled Rust package (oaptpclock_rs).

3. Hardening PTP Compiler Hooks

  • Issue: Risk of externally-managed-environment errors and stale binary imports during pip operations within the oaPTP compiler hooks.
  • Root Cause: Lack of PEP 668 overrides and specific class verification logic in the oaPTP compiler hook templates.
  • Resolution: Updated the compiler_hook.py scripts for oaPtpParser_rs and oaPTPClock_rs to include robust cleanup, explicit venv Python routing, the PIP_BREAK_SYSTEM_PACKAGES environment variable override, and verified class imports.

Verification

The fixes ensure that the oaPTP module can now correctly locate and execute its compiler hooks during bootstrap, and its internal components can successfully bind to the high-performance Rust PTP engines.
