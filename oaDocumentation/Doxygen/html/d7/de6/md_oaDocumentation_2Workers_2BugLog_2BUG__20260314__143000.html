Bug Report: [MQTT] SyntaxError in MqttConnectionManager

📅 Timeline

  • Discovery Date: 2026-03-14 14:30:00
  • Resolution Date: 2026-03-14 14:40:00
  • Priority: 1 (Critical/Crash)

🔍 Issue Summary

The MqttConnectionManager module failed to import, causing a ‘SyntaxError: expected 'except’ or 'finally' block. This error originated from an unclosedtryblock in the_queue_worker_task` method, effectively crashing both UI and Core partitions upon startup.

🪱 Root Cause

The _queue_worker_task method (which manages the asynchronous publication and subscription queues) contained a try block that started but was never closed with an except or finally clause before the next method definition (disconnect). This resulted in an illegal Python syntax state.

🛠️ Resolution

  1. Fixed SyntaxError: Completed the try-except-finally block for _queue_worker_task.
  2. Optimized Async Loop: Added if not processed_anything: await asyncio.sleep(0.01) at the end of the worker loop to prevent a high-CPU "busy loop" state when the queues are empty.
  3. Enhanced Exception Handling: Implemented proper asyncio.CancelledError and Exception handling for the worker thread, ensuring errors are logged and don't cause silent thread termination.

✅ Verification Evidence

  • Empirical Proof: Verified successful import of MqttConnectionManager via CLI.
  • Command: ‘python3 -c "from oaComBroker.mqtt.mqtt_connection import MqttConnectionManager; print('Import Successful&rsquo;)"
  • **Result**:Import Successful`

📋 System Impact

  • System Bootstrap: Restored.
  • CPU Usage: Improved by adding an async yield (sleep) in the hot worker loop.
  • MQTT Stability: Enhanced reliability of the background worker thread.
