Bug Report: Test Discovery ImportError

Date: 2026-04-09
Status: Resolved
Priority: 2 (High/Spam - Blocks Tests)

1. Issue Description

Automated test discovery was failing with ImportError: Start directory is not importable for several modules.

Evidence:

  • ERROR | TestRunner:run:105 - ❌ ImportError in .../oaComNmos/Core/IS12/Tests: Start directory is not importable
  • ERROR | TestRunner:run:105 - ❌ ImportError in .../oaGui/Tests: Start directory is not importable

2. Root Cause Analysis

The Python unittest discovery engine requires directories containing tests to be valid Python packages. Several newly created or refactored Tests directories were missing the mandatory __init__.py marker, preventing the runner from traversing those paths.

3. Resolution Strategy

  • Surgical Creation: Manually created missing __init__.py files in the reported directories.
  • Systemic Sweep: Executed a workspace-wide shell script to identify and populate any other Tests folders missing package markers.

4. Verification Evidence

  • Discovery Check: Confirmed that the test runner no longer reports ImportError for the affected paths.
  • Package Audit: Verified presence of __init__.py across all oa* module test folders.

5. System Impact

  • Test Integrity: Restored full coverage for the automated CI/CD pipeline.
  • Development Stability: Prevented silent regressions in modules where tests were previously skipped due to discovery failure.
