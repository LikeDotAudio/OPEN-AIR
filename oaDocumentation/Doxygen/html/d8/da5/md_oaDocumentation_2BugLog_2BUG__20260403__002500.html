Bug Resolution: Resource Leaks and N+1 MQTT Query

Date: 2026-04-03 Author: Elite Bug-Fixing Architect

Issue

  1. Resource Leaks: Multiple socket initializations in oaComProtocols.oaComVisa/Methods/network_utils.py, oaComProtocols.oaComVisa/Workers/agent_mdns_zeroconf.py, and oaComProtocols.oaComVisa/Methods/visa_utility_parser.py did not guarantee socket closure via finally blocks or context managers, risking "Too many open files" errors.
  2. N+1 Query Pattern: The _update_found_devices_gui method in oaComProtocols.oaComVisa/Workers/logic_mqtt_publisher.py executed up to 120 separate non-blocking MQTT publish operations sequentially to populate the GUI dropdown, causing potential network overhead and UI stutter.

Root Cause

  • Sockets were initialized using sock = socket.socket(...) and closed sequentially, without safeguards to ensure .close() would execute if a TimeoutError or connection exception occurred.
  • The MQTT logic for updating found devices directly mirrored the GUI slots by publishing options/i/active individually in a for loop.

Resolution

  1. Resource Safety: Refactored check_host() in oaComProtocols.oaComVisa/Methods/network_utils.py, _check_host() in oaComProtocols.oaComVisa/Workers/agent_mdns_zeroconf.py, and query_device_safe() in oaComProtocols.oaComVisa/Methods/visa_utility_parser.py to employ with socket.socket(...) as sock: context managers. This automatically handles graceful shutdown of file descriptors on exit or exception.
  2. Bulk MQTT Updates: Modified _update_found_devices_gui() in oaComProtocols.oaComVisa/Workers/logic_mqtt_publisher.py to construct a single consolidated JSON array (options_array) of all 40 slots, then published it as a single atomic operation to the bulk endpoint options/all.

Verification Evidence

  • Verified syntax correctness for context managers.
  • Verified single bulk publish reduces the 120 calls down to 1 primary bulk payload (plus the auto-selected trigger).
