BUG: TypeError in Recursive GUI Build Process

  • ID: 20260314_160625
  • STATUS: RESOLVED
  • SEVERITY: 1 (Critical)
  • COMPONENT: oaGuiBuild.Managers.engine_gui_display, oaGui.parser.layout_parser

Issue

The GUI build process was crashing with a TypeError when processing a layout.json file that used the recursive_build type with nested layouts (i.e., a child_containers item that was a dictionary itself instead of a file path). The application would only partially render the UI and then halt, as seen in the logs where a critical exception terminated the build thread.

Root Cause Analysis

  1. Type Mismatch: The _process_recursive function in engine_gui_display.py was designed to handle a list of file paths (str or pathlib.Path). It iterated through its all_items list and passed each item directly to self.loader_facade.load_and_instantiate_gui, which expects a file path.
  2. Nested Layouts: When a layout.json defined a nested layout, one of the items in the child_containers list was a dict, representing the layout definition for the child.
  3. The Crash: Passing this dict to load_and_instantiate_gui caused a TypeError because the function tried to perform file-system operations on a dictionary, which is not a valid path object. This exception was caught by the top-level handler, which terminated the build for that branch of the GUI.
  4. Inconsistent Parsing: The FolderLayoutInterpreter had logic to parse layout.json files, but there was no public method to re-run this parsing logic on a dictionary that had already been loaded, leading to the type mismatch downstream.

Resolution

A two-part refactoring was implemented to make the layout processing robust and type-safe:

  1. Refactored FolderLayoutInterpreter:
    • A new public method, parse_layout_data(layout_data, source_path), was created. This method contains the core logic for parsing a layout dictionary, resolving relative paths within it, and returning a standardized data structure.
    • The existing parse_directory method was updated to simply load a layout.json file and then call parse_layout_data to process it. This ensures both file-based and dictionary-based layouts go through the exact same parsing logic.
  2. Refactored engine_gui_display.py:
    • The _build_from_directory function was replaced with a new version that accepts a layout_override dictionary. This allows it to receive nested layouts directly.
    • The _process_recursive function was updated with a crucial type-check. It now inspects each item in its list:
      • If isinstance(item, dict), it recognizes it as a nested layout and calls self._build_from_directory, passing the dictionary as the layout_override.
      • If isinstance(item, (str, pathlib.Path)), it proceeds as before, loading it as a standard GUI file.

This change ensures that nested layout dictionaries are correctly re-parsed and built recursively, fixing the TypeError and allowing the entire GUI to load as designed.

Verification

The application now fully loads the GUI without any TypeError exceptions in the log. All components defined in nested recursive_build layouts are correctly rendered in their designated slots.
