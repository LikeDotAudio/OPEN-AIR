BUG: GUI Layout Regression from Directory Name Parsing

  • ID: 20260314_161529
  • STATUS: RESOLVED
  • SEVERITY: 2 (High)
  • COMPONENT: oaGui.parser.layout_parser

Issue

The GUI was failing to create the main horizontal 50/50 split view defined by the oaGui/Assets/left_50 and oaGui/Assets/right_50 directory structure. Instead of creating a ttk.PanedWindow, it was treating the subdirectories as simple content folders, causing them to render incorrectly as stacked elements rather than side-by-side panes. This was a regression introduced during a recent refactoring of the layout parsing logic.

Root Cause Analysis

The refactoring of the FolderLayoutInterpreter class in the previous fix introduced a logic error in the _parse_directory_listing method. This method is the fallback for when no layout.json is found in a directory.

The previous implementation of this method correctly identified subdirectories named with the left_ or right_ prefix, interpreted them as a horizontal_split layout, and parsed the percentage values. The refactored version, however, had this logic stripped out. It was only identifying "content" directories and "gui files", completely ignoring the directory names that are intended to define the window layout. As a result, when _build_from_directory in engine_gui_display.py called the parser for the main display directory, the parser was returning a directory_listing type instead of the expected horizontal_split type, breaking the layout.

Resolution

The logic for parsing layout-defining directory names was restored and corrected within the _parse_directory_listing method in managers/Display/parser/layout_parser.py.

  1. The function now explicitly checks for the presence of directories starting with left_, right_, top_, or bottom_.
  2. If found, it determines the layout type (horizontal_split or vertical_split).
  3. It then correctly parses the percentage values from the directory names (e.g., 50 from left_50).
  4. Finally, it returns a structured dictionary with the correct layout type and the parsed panel data (paths and weights).
  5. If no such layout-defining directories are found, it proceeds with the fallback behavior of returning a simple directory_listing.

This change restores the critical functionality of defining layouts via directory naming conventions, fixing the regression.

Verification

After the fix, the application correctly renders the main display with a 50/50 horizontal split. The left_50 and right_50 directories are now correctly interpreted as panels in a ttk.PanedWindow, and the GUI appears as intended. Log files now show that the FolderLayoutInterpreter correctly identifies the horizontal_split type for the display directory.
