Bug Log: 20260417_000500

Description

TypeError: can only concatenate str (not "int") to str and ‘AttributeError: 'Frame’ object has no attribute 'variable'occurring during the instantiation of theOcaCompositeFaderKnobwidget (composite_horizontal_dial_value.py`).

Error Clusters

  • Cluster A: Tuple Unpacking Failure: TypeError in tkinter.cget caused by a tuple being passed as a widget parent.
  • Cluster B: Ghost Mode Sync Crash: AttributeError when attempting to bind trace_add to .variable on ghost-rendered sub-widgets that lack full initialization attributes.

Trigger Event

GUI Rebuild or initial rendering of a composite widget, especially while in "Ghost" or "Fast" render tiers (which occurs during drag-and-drop operations).

Domain Mapping

  • oaGuiElements/Core/utils/composite_horizontal_dial_value/composite_horizontal_dial_value.py
  • oaGui/Core/base_widget_creator.py

Action Taken

  1. Unpacking Removal: Reverted the tuple unpacking in composite_horizontal_dial_value.py to fader_widget = self.make_fader_horizontal(...) since BaseWidgetCreator.build was recently refactored to return only the single widget instance, not a (widget, canvas) tuple.
  2. Ghost Awareness: Added a safety check (‘is_ghost = not hasattr(fader_widget, 'variable’) or not hasattr(dial_widget, 'variable')) to the state synchronization block in_assemble_ui. This prevents the builder from attempting to bind variable traces to lightweight ghost placeholders.
  3. **Log Noise Reduction**: Removed noisy repetitive logging calls fromTransparencyMixin.register_for_bg_sync()`.

Verification Results

  • Composite dial and fader widgets successfully instantiate during both High-Res and Ghost render tiers.
  • TypeError inside tkinter.cget is resolved.
  • Drag-and-drop operations involving composite widgets no longer crash the rendering sequence.
