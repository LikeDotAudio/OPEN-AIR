BUG: PanedWindow Sash Dragging Disabled

  • ID: 20260314_191713
  • STATUS: RESOLVED
  • SEVERITY: 3 (Moderate)
  • COMPONENT: oaGuiBuild.Managers.gui_display

Issue

The sash dividers in ttk.PanedWindow widgets could not be moved by the user via a click-and-drag mouse action. While the panes were being laid out with the correct proportions programmatically, the user had no ability to manually override or adjust them, which is a core feature of a paned window.

Root Cause Analysis

During a previous debugging session for layout recursion issues, a line of code was added to the _build_from_directory function in gui_display.py:

paned_window.bind("<B1-Motion>", lambda e: "break")
vector
vector
Definition generated.rs:2773

This line binds to the left-mouse-button-drag event (<B1-Motion>) for all created PanedWindow widgets. The lambda function returns the string "break". In the Tkinter event model, returning "break" from an event callback stops the event from propagating further. This effectively cancelled the default drag behavior of the sash, preventing the user from being able to move it. This line was intended to be a temporary debugging measure but was accidentally committed.

Resolution

The fix was to simply remove the erroneous line of code.

  1. The line paned_window.bind("<B1-Motion>", lambda e: "break") was deleted from the horizontal_split/vertical_split block in the _build_from_directory method.

This action restores the default event handling for the ttk.PanedWindow sash, allowing users to click and drag it to resize the panes as expected. The programmatic layout via the <Configure> event still works correctly to set the initial and resized proportions, while the user now has the ability to manually adjust them.

Verification

After the fix, all sashes in the application can be freely moved by clicking and dragging with the mouse. The initial layout proportions are still correctly set, and the layout continues to update correctly when the main application window is resized.
