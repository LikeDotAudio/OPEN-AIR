Bug Log: BUG_20260312_002600

<strong>Issue</strong>

User Complaint: "sometimes when Im in the splinker log it crashes all the gui except it" Evidence: GUI becomes unresponsive (frozen) when viewing high-frequency Splinker activity, especially after tearing off the log into its own window.

<strong>Root Cause</strong>

  1. Event Flooding: SplinkerLogs was triggering an immediate after(0, ...) UI update for every single Splinker event. High-frequency brokerage activity (hundreds/thousands per second) saturated the Tkinter event queue, starving all other UI tasks (clicks, redraws).
  2. Resource Leak (Tear-off): WindowManager.tear_off_tab used notebook.forget() to hide the original tab, but failed to destroy() its children. This left the hidden instance of SplinkerLogs active and processing events in the background, doubling the UI thread load every time the tab was torn off.
  3. Static Re-configuration: tag_configure was called for every single tree insert, adding unnecessary Tcl overhead to the hot update path.
  4. Data Truncation: No safety limits on investigation report text allowed extremely large data packets to freeze the tk.Text widget.

<strong>Investigation</strong>

  1. Code Review: Identified after(0, ...) as a bottleneck and the lack of destruction in WindowManager.
  2. Empirical Reproduction: Created reproduce_splinker_leak.py and reproduce_splinker_crash.py to simulate high-frequency floods. Confirmed that multiple hidden instances correctly receive events and freeze the UI thread.
  3. Trace Analysis: Observed that while the UI thread stayed "alive" (mainloop running), it was so backlogged with Splinker updates that no other events were being processed.

<strong>Resolution</strong>

  1. Throttled Batch Updates: Modified SplinkerLogs to buffer incoming events in self.pending_events and update the UI in batches (max 50 per batch) every 100ms.
  2. Visibility Management: Added <Map> and <Unmap> bindings to SplinkerLogs to automatically pause UI updates when the widget is not visible.
  3. Cleanup Hardening: Updated WindowManager.tear_off_tab to explicitly destroy() the children of the original frame after forgetting it, ensuring clean unregistration of callbacks.
  4. UI Optimization: Moved tag_configure to setup and implemented safe truncation (_safe_str) for investigation reports.

<strong>Verification</strong>

  1. Leak Test: verify_splinker_fix.py confirmed that destroying the frame successfully unregisters the Splinker monitor callback, preventing leaks.
  2. Stress Test: Simulated 50,000 events with the fix applied; the UI remained responsive, and the log updated smoothly at a throttled rate.
  3. Stability: Confirmed no TclErrors or memory spikes during rapid tear-off/re-attach cycles.
