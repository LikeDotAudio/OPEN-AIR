BugLog Entry: 20260409_004400

Issue Summary

The WebSocketEventTransport in oaComProtocols.oaComWebsocket was generating noisy WARNING logs when a server was unavailable (Connection Refused). During system boot, this led to log clutter as multiple modules attempted to connect before the infrastructure was ready.

Root Cause Analysis

  • Missing Reconnect Logic: The transport attempted to connect only once and returned failure if the server was down.
  • Log Level Inflexibility: Connection failures were always logged as WARNING, regardless of whether they were expected retries or critical failures.

Resolution

  • Background Reconnection: Implemented an asynchronous reconnection mechanism in WebSocketEventTransport.
  • Log Level Demotion: Refactored _on_error to demote "Connection Refused" errors to DEBUG level when a reconnection loop is active, while maintaining WARNING for the initial failed attempt.
  • Improved Management: Added reconnect and reconnect_interval parameters to the connect method.
  • Dependency Fix: Installed missing websocket-client dependency in the environment.

Verification Evidence

  • Reproduction Script: Ran .gemini/TempScripts/reproduce_ws_noise.py.
  • Observed Behavior:
    1. Initial failure logged as WARNING.
    2. Subsequent background retry failures logged as DEBUG.
    3. Total log noise reduced significantly for the end-user.
