# Bug Report: Splinker Transmission NameError (Missing Import)

## Issue
**User Complaint**: Log shows `Splinker Transmission Error: name 'threading' is not defined`.
**Evidence**: Multiple error logs in both CORE and UI partitions during Splinker activity.

## Root Cause
The previous task implemented **Per-Splink Execution Locks** using `threading.Lock()` inside `workers/Splinker/core/process_router_event.py`, but the `import threading` statement was omitted from that specific file. This caused a `NameError` every time a router event matched an active Splink.

## Investigation
- **Logs**: Identified `Splinker Transmission Error: name 'threading' is not defined` recurring at high frequency.
- **Code Review**: Confirmed `threading.Lock()` usage in `process_router_event.py` without a corresponding import at the top of the file.

## Resolution
- **Fix**: Added `import threading` to `workers/Splinker/core/process_router_event.py`.
- **Validation**: Verified that all other files in the Splinker manager sub-package either have the necessary imports or do not use `threading`.

## Verification
- **Test Case**: Monitored the logs during bidirectional Splink activity.
- **Result**: The `NameError` is resolved, and the execution locks are now correctly functional, preventing feedback loops as intended.
