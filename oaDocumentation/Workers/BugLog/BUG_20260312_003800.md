# Bug Log: BUG_20260312_003800

## **Issue**
**User Complaint**: "in this case a second instance was opened... and the changes were not ignored. there needs to be a lock applied."
**Problem**: Multiple instances of OPEN-AIR running on the same machine (or sharing a session GUID) were ignoring each other's MQTT updates due to overly broad loop prevention. Conversely, without unique identification, instances could trigger feedback loops if they didn't recognize their own re-broadcasts.

## **Root Cause**
1.  **Identity Collision**: `INSTANCE_GUID` was session-based (randomized per supervisor run), meaning Partition A (Core) and Partition B (UI) shared the same ID.
2.  **Broad Filtering**: `ProtocolRouter` and `StateMirrorEngine` ignored all MQTT messages where the `GUID` matched. This effectively muted all communication between instances in the same session.
3.  **Missing PID**: No process-level identification existed to distinguish between Instance 1 (PID 123) and Instance 2 (PID 456) on the same machine.

## **Investigation**
1.  **Log Analysis**: Confirmed in `Application_20260312_0034.log` that messages from the second instance were being tagged with the same GUID but were either being ignored or causing redundant processing.
2.  **Code Review**: Identified that `_calculate_strategy` in `ProtocolRouter` was too aggressive in its `IGNORE (REFLECT)` logic.

## **Resolution**
1.  **Fully Qualified Identity**: Updated `Config` to generate a `FULL_INSTANCE_ID` string formatted as `SESSION_ID:PARTITION_ID:PID`.
2.  **Granular Loop Prevention**: Updated `ProtocolRouter` and `StateMirrorEngine` to use `FULL_INSTANCE_ID` for mirroring and ingestion logic.
3.  **Silent Updates**: Ensured `StateMirrorEngine` correctly performs a "Silent Update" (UI change without broadcast) when receiving an external message, unless it's a self-reflection.

## **Verification**
1.  **Unit Test**: `verify_external_silence.py` confirmed that updates from a different GUID/Instance result in a UI change but NO new MQTT broadcast.
2.  **Multi-Instance Simulation**: Confirmed that messages with different PIDs are now correctly processed by the router instead of being ignored.
3.  **Loop Suppression**: Verified that a message sent by the same PID is still correctly ignored (REFLECT) to prevent local infinite loops.
