# BUG: VISA Scan Timeouts & Unhandled Exceptions
- **ID**: 20260314_155045
- **STATUS**: RESOLVED
- **SEVERITY**: 1 (Critical)
- **COMPONENT**: `oaComProtocols.oaComVisa.Visa_Fleet.visa_Search`

## Issue
During a VISA fleet scan, network instruments that were slow to respond were causing `socket.timeout` errors. These timeouts were not being handled gracefully, leading to raw error messages in the log (e.g., "Error closing VISA link: socket.timeout"). More importantly, this caused the `manager_visa_Search` module to fail to identify these devices, marking them as "Unresponsive". As a result, the downstream GUI builder (`YakFleetCommandBuilder`) would not receive the device information and would fail to create the necessary command and control tabs for these instruments, making them inaccessible to the user.

## Root Cause Analysis
1.  **Aggressive Timeout**: The `VISA_TIMEOUT` constant in `manager_visa_Search.py` was set to 1000ms. This was insufficient for some network-connected VISA devices, especially on congested networks or for devices that are slow to process initial connections.
2.  **Unhandled Exception**: The main `probe_devices` loop did not have a specific exception handler for `socket.timeout`. While `_query_device_safe` handled `pyvisa.errors.VisaIOError`, a raw socket timeout could still occur and propagate, causing an ungraceful failure message.
3.  **Missing Import**: The fix introduced a dependency on the `socket` module without importing it, which would have caused a `NameError`.

## Resolution
1.  **Increased Timeout**: The `VISA_TIMEOUT` in `manager_visa_Search.py` was increased from 1000ms to 2500ms to provide more tolerance for slow network devices.
2.  **Structured Exception Handling**: A `try...except socket.timeout` block was wrapped around the `_query_device_safe` call within the `probe_devices` function. This now catches the specific timeout error, logs a standardized warning message (`💳⚠️ [TIMEOUT]`), and allows the loop to continue to the next device gracefully.
3.  **Added Import**: An `import socket` statement was added to the file to resolve the dependency.

## Verification
After the fix, VISA scans now correctly identify the previously unresponsive network devices. The application successfully builds all the corresponding GUI tabs, making the instruments available for control. The unhandled `socket.timeout` error is no longer present in the logs, having been replaced by the standardized warning.
