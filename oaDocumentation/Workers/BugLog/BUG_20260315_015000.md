# Bug Log: BUG_20260315_015000
**Date:** Sunday, March 15, 2026  
**Module:** `oaComVisa.Visa_Fleet`, `oaPTP`  
**Severity:** Priority 1 (VISA) / Priority 2 (PTP)

## Issue
1. **Silent VISA Failures**: `manager_visa_Search` was reporting `FAILED (IDN Query Error)` without any underlying diagnostic information. This made it impossible to determine why specific instruments were failing to respond during discovery.
2. **PTP Permission Spam**: The `PtpManager` sniffer would attempt to start and fail with a `PermissionError` on every session launch or retry, cluttering the logs with repetitive warnings when the application was not run as root.

## Root Cause
1. **Error Swallowing**: `VisaUtilityParser.query_device_safe` was catching all exceptions and returning `None` silently. The caller (`manager_visa_Search`) could only report a generic failure.
2. **Missing State Logic**: `PtpManager` lacked a mechanism to remember that a previous attempt to start the sniffer failed due to permanent permission restrictions (i.e., not running as sudo).

## Resolution
1. **Diagnostic Enhancement**: 
   - Modified `VisaUtilityParser.query_device_safe` to explicitly catch `pyvisa.errors.VisaIOError` and other `Exception` types.
   - Added `logger.debug` and `logger.error` calls to capture specific error descriptions and codes from PyVISA and the socket layer.
2. **Log Suppression**:
   - Added `permission_error_reported` flag to `PtpManager.__init__`.
   - Updated `PtpManager.start()` and `_run_sniffer()` to set this flag and prevent future start attempts if a `PermissionError` occurs.

## Verification
- **PTP Fix**: Verified by inspecting code logic. The `permission_error_reported` flag is persistent across `start()` calls within the same session.
- **VISA Fix**: Verified by inspecting code logic. The logger will now output `[VISA ERROR]` or `[EXCEPTION]` with full details instead of just returning `None`.

## Forensic Evidence
Log snippets from `Application_20260315_0127.log` showed a 13ms failure for `TCPIP::44.44.44.66::INSTR`, suggesting an immediate library-level exception that was being swallowed.
