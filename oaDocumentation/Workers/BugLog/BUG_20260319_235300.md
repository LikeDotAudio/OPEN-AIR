# Bug Report: ModuleNotFoundError in oaGuiManager

## Issue
The application failed to launch because `oaGuiManager` components were unable to find internal modules like `Constants` and `Methods` when using relative imports within the nested `Core/parser` and `FileReaders` subpackages.

## Root Cause
A recent architectural refactoring moved files into a `Core` subdirectory, breaking existing relative imports (e.g., `..Constants.schema_defaults`) because the package boundaries were not correctly handled by the Python interpreter in the new structure.

## Resolution
Converted all problematic relative imports to absolute imports using the top-level `oaGuiManager` package name. This ensures that modules are correctly located regardless of the execution context or the depth of the importing module.

## Files Modified
- `oaGuiManager/Core/parser/widget_schema_normalizer.py`
- `oaGuiManager/FileReaders/blueprint_loader.py`
- `oaGuiManager/Methods/schema_utils.py`

## Verification Evidence
Execution of `OpenAir.py` shows the Core partition successfully completing its initialization sequence and the UI partition successfully reaching the `tk.Tk()` initialization stage.
