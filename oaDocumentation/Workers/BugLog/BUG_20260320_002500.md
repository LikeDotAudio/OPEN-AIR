# Bug Report: Comprehensive GUI Rendering & Stability Fixes

## Issue
Multiple rendering and stability issues were reported across various GUI components:
1. `7_Data/2_demo` crashed the project during bootstrap.
2. `blinky_winky` and `VU_Meter_Knob` were invisible.
3. `CMDP` threw an `AttributeError` on interaction.
4. `XY Graphs` were not displaying plot data or axes.

## Root Cause Analysis
1. **GuiTable Crash**: During initial data loading, the table was broadcasting every row to MQTT via `TableSyncEngine`. During the bootstrap phase, this high-volume asynchronous traffic created a feedback loop or race condition that stalled the application.
2. **Invisible Buttons/Meters**: Older JSON definitions used `widget_type` instead of `type`, which the builder was silently skipping after recent refactoring.
3. **CMDP Attribute Error**: The `refresh_pop_tree` method was not implemented in the new modular `CMDPWidget` class, but was still called by its group and file handlers.
4. **Invisible Graphs**: `GraphPatinaMixin` was hiding the Matplotlib axes patches (`set_visible(False)`) when "transparent" or "match_theme" backgrounds were used. This prevented the blit engine from capturing a valid background buffer, resulting in empty/black plots.

## Resolutions
1. **Table Stability**: Added a `suppress_mqtt` flag to `TableSyncEngine.update_full` and enabled it for the initial configuration data load.
2. **Schema Standardization**: Batch-replaced `widget_type` with `type` in `blinky_winky.json` and `VU_Meter_Knob.json`.
3. **CMDP Interface**: Added the missing `refresh_pop_tree` method to `CMDPWidget` as a public alias for the tree manager's refresh logic.
4. **Graph Visibility**: Updated `GraphPatinaMixin` to use `set_alpha(0.0)` instead of `set_visible(False)`. Forced an initial redraw in `GraphPlotter` initialization to prime the blit cache.
