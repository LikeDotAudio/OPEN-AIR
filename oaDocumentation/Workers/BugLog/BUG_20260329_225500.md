# Bug Report: BUG_20260329_225500

## Issue
1.  **Empty Main GUI**: Complex GUI definitions (like the mixing consoles) appeared empty when loaded in the main application, even though they showed content in the editor.
2.  **Empty Editor Tree**: The "Structure" tree in the WYSIWYG editor was empty when loading files, even if the interactive layout showed widgets.

## Root Cause
1.  **Visibility Failure**: `BuilderArrayCreator.make_array` was creating its own `main_container` (a tk.Canvas) but never calling `grid()` or `pack()` to place it in the parent. This resulted in the array and its children being instantiated but remaining invisible.
2.  **Tree Sync Failure**: The `TreeRefactor` tab in the editor was subscribing to `STATE_UPDATED` events after the initial state was already loaded, missing the initial population trigger.
3.  **Root Key Misalignment**: The tree population logic did not correctly handle GUI definitions that use a single named root key (e.g., `"Console_9-16": { ... }`), causing the recursive walk to stall at the top level.

## Resolution
1.  **Mandatory Gridding**: Updated `oaGui/Core/array/array.py` to explicitly call `grid()` on the `main_container` using layout metadata from the JSON.
2.  **State Sync on Init**: Updated `oaGuiEditorWYSIWYG/Core/workspaces/tree_refactor.py` to fetch the current state from `StateManager` immediately upon creation.
3.  **Improved Tree Logic**: Enhanced `_populate_tree` to detect single-key root containers and correctly descend into standard keys like `blocks`, `fields`, and `items`.

## Verification
1.  Manual audit of the grid logic confirms that `main_container` now participates in the Tkinter geometry management.
2.  The editor now correctly populates the hierarchy tree for console JSON files.
