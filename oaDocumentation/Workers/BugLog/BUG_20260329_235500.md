# Bug Report: BUG_20260329_235500

## Issue
Global and local debug flags were fragile, primitive, and caused "log firehose" problems where high-velocity comms logs would drown out UI or core logic debugging.

## Root Cause
The previous system relied on hardcoded `LOCAL_DEBUG` booleans in every file. There was no way to enable debugging for a specific element (like MQTT) while keeping the rest of the system quiet, or to mute specific high-frequency functions.

## Resolution
Implemented a **Hierarchical Debug Matrix** architecture:
1.  **Centralized Control**: Added `[DEBUG_MATRIX]` section to `config.ini`.
2.  **Lookup Hub**: Created `LoggingMatrixManager` in `oaConfigurationManager/Managers/LoggingManager/`.
3.  **Surgical Gating**: Added `is_debug_allowed`, `@debug_matrix`, and `matrix_log` to `oaLogging`.
4.  **Tiered Hierarchy**: Supports:
    - **Master Switch**: Overrides everything.
    - **System Level**: Macro control (COMMS, GUI, DATA).
    - **Element Level**: Specific modules (MQTT, SNMP, BUILDER).
    - **Function Level**: Precise inclusions/exclusions (mute `update_canvas`, force `critical_error`).

## Verification
1.  Verified that `config.ini` settings are correctly parsed by `Config.get_instance()`.
2.  Verified that `SNMPManager` now dynamically determines its `LOCAL_DEBUG` state based on the matrix.
3.  Manual tests confirm that setting `SYS_COMMS = False` but `ELEMENT_MQTT = True` works as intended.
